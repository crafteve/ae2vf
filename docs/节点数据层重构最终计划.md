# 节点数据层重构最终计划

> 状态：待执行
> 最后更新：2026-11-04
> 修订：2026-11-04 按审查意见修订（协议阶段、统一测试、NextSeq、绑定事务、虚拟节点定位、硬上限、AGENTS/ADR、P1 拆分）。
> 依据：[15-节点数据层重构确认](草稿纸/15-节点数据层重构确认.md)
> 目标：把“1 机器 = 1 节点 = 1 方块”改成“节点 → 机器 → 方块”，并完成节点级 IO、provider、绑定杖草稿、v3 IO 终端节点卡片与相关指令/诊断。
> 非目标：不改玩法数值、不改美术语言、不新增资源类型、不为旧档写迁移、不改 `AGENTS.md`。

---

## 0. 最终结论摘要

- 三层：**节点 → 机器 → 方块**。
- 节点 id、机器 id 都是随机 UUID；方块 key 只表示位置，不派生任何 id。
- 节点、机器都不存维度；维度在方块上。节点内机器可跨维度；同一台机器内部方块也可跨维度；任何方块不可用 → 整台机器 OFFLINE。
- 节点类型只认**主方块 id**：单方块机器看唯一方块，多方块机器看主方块；部件不参与类型判定。
- 节点内所有机器必须同一种主方块 id；部分机器掉线时，原地出现不同方块不认；所有机器都掉线且主方块统一变成另一个 id 时，节点自动迁移类型。
- `MachineHealth` 只有 ONLINE/OFFLINE；`NodeHealth` 只有 ONLINE/PARTIAL/OFFLINE；方块级 `Health` 仅用于诊断。
- IO 规则归节点；堆叠机器共用一套；只跑 ONLINE 的机器。
- provider 归节点；一个节点一个 `PatternContainer`；一次货只给一台机器；收不下进余量队列，余量条目绑定原机器，不拆分。
- 智能倍率按“一台机器能装几份”算；探测失败回退 ×1；输入输出同倍。
- 多方块 provider 对整台机器的所有方块开面，优先主方块，再逐个部件；阻挡/回收也扫所有方块。
- 绑定杖使用**客户端草稿物品组件 + 完成时一次提交**；无服务端会话、无时间限制、不校验距离；草稿不跨登录保留。
- v1 `FactoryScreen` 是废弃兜底，只做编译机械适配；v3 `FactoryPassiveIo*` 改成节点大卡片。
- 所有玩法上限进 config，默认 `-1` 无上限；但有一组不可关的硬上限（倍率/线协议/余量/样板容量），防止溢出与恶意包。
- 旧档不迁移；测试世界重建。

## 1. 目标模型

### 1.1 三层与不变量

```text
Node
 ├─ id: UUID（随机）
 ├─ name: String / null
 ├─ typeBlockId: ResourceLocation   // 节点类型 = 主方块 id
 ├─ io: NodeIoGroup
 ├─ provider: NodeProvider
 └─ machines: List<Machine>          // 加入顺序稳定，不按坐标/状态重排
      └─ Machine
           ├─ id: UUID（随机）
           └─ blocks: List<BlockKey> // 每块自带维度；第 0 块是类型/展示方块
```

不变量：

1. 节点至少 1 台机器；机器至少 1 个方块。
2. 同一台机器的所有方块不要求同维度；任一方块不可用 → 机器 OFFLINE。
3. 节点内所有机器的 `blocks.get(0)` 类型方块 id 必须等于 `Node.typeBlockId`；例外只有“全离线自动迁移”。
4. 每台机器都用 `blocks.get(0)` 作为类型/展示方块；单方块机器只是退化情况，不单开“没有主方块”的分支。
5. 节点 id、机器 id 随机生成；加/删方块、换类型方块不改机器 id。
6. 方块全局唯一：一个 `BlockKey` 只能属于一个节点的一台机器。
7. 机器列表顺序 = 加入顺序；不按坐标或状态重排。
8. 运行时游标（派单/IO 轮转）只存内存，不写档。

`Machine.typeBlock()` 固定返回 `blocks.get(0)`；单方块机器这就是唯一方块，多方块机器这就是主方块 / 展示方块。所有需要“类型方块/图标/定位”的地方都用它，不再区分“有没有主方块”。

**Node 的可变性选型：浅不可变聚合。**

- `Node` 的字段全部 `final`：`id`、`name`、`typeBlockId`、`io`、`provider`、`machines`（不可变列表）、`topologyRevision`。
- `io` / `provider` 仍是可变对象，由节点持有；结构变更（加/删机器、换 typeBlock）返回新 `Node`，**共享同一个 io/provider**，不复制规则和样板。
- 提供 `withName`、`withTypeBlockId`、`withAddedMachine`、`withRemovedMachine`、`withReplacedMachine`；每次结构变更 `topologyRevision + 1`，名字/规则/阻挡等非结构变更不 +1。
- 运行时唯一写入口是 `NodeLibrary.replace(Node)`；`Node` 自己不维护全局索引，不直接改 `NodeLibrary`。

### 1.2 身份与类型

- **节点 id**：随机 UUID；1:1 时不再等于机器 id。
- **机器 id**：随机 UUID；不再由方块 key 派生。
- **BlockKey**：`(dimension, pos)`，只用于观测、占用、路由、定位。
- **节点类型**：`Node.typeBlockId` 持久化。
  - 单方块机器：`blocks.get(0)` 的方块 id。
  - 多方块机器：`blocks.get(0)`（主方块）的方块 id。
  - 部件（输入输出总线、外壳等）不参与类型判定。
- **自动迁移**：
  - 只要还有机器 ONLINE，缺失机器原地出现不同方块 → 不认，保持 missing。
  - 当节点所有机器都 OFFLINE，且所有机器的 `blocks.get(0)` 都观测为 PRESENT、blockId 非空、且都是**同一个新 id**、且不等于当前 `typeBlockId` → 更新 `typeBlockId`，节点迁移类型；节点 id、规则、样板、名字、机器 id 全部保留。
  - 部分换、类型不一致、类型方块空气/未加载 → 不迁移。
  - 单机器节点同样适用：唯一机器掉线且被换成另一类机器时，节点认新类型。
- **对账版本**：`Node` 有一个仅运行时的 `topologyRevision`，机器/方块/类型变化时 +1；`NodeRuntime.matches` 比较 factoryId + nodeId + anchor + topologyRevision，不比较对象身份。

### 1.2.1 视图字段（节点/机器可能跨维度）

- `NodeView`：`nodeId`、`name`、`typeBlockId`、`health`（NodeHealth）、`probed`（是否所有机器都探过）、`stale`（是否有机器健康过期）、`machineCount`、`onlineMachineCount`、`blockCount`、`ruleCount`、`patternCount`、`provider`、`members`；**去掉 `machineMissing`**，健康统一由 `health` 表达。
- `MemberView`：`machineId`、`blocks: List<BlockKey>`、`blockId`（`blocks.get(0)` 观测 id）、`health`（MachineHealth）、`probed`、`stale`；**不再有单一 `dimension` 字段**；需要类型方块时用 `typeBlock()`。
- `MachineView`（v1/v3 机器表）：`nodeId`、`nodeName`、`nodeIconBlockId`、`nodeMachineCount`、`machineId`、`primaryBlock`（维度 + 坐标）、`blockCount`、`health`（MachineHealth）、`probed`、`stale`、规则字段；v3 按 `nodeId` 分组，图标用 `nodeIconBlockId`，数量用 `nodeMachineCount`。
- `probed` 定义：
  - 方块：`Observation.health() != UNKNOWN`。
  - 机器：**所有方块**都 probed。
  - 节点：**所有机器**都 probed。
  - 任一机器未 probed → 节点 `probed=false`，tooltip“未探测”；不新增第四个 NodeHealth 状态。
- `stale` 定义（机器级一个布尔，方块级留在 `BlockObservation` 内部，不进协议）：
  - 方块：`now - lastProbeTick > staleHealthTicks`。
  - 机器：**任一方块** stale。
  - 节点：**任一机器** stale。
  - `probed=false` 是“没探过”，`stale=true` 是“探过但过期”；两者可独立组合，不塞进 `NodeHealth`。
- 协议里 `MemberView` 的每个方块都要写“维度 + 坐标”，不能只写一个维度再跟坐标列表。

### 1.3 健康

```text
MachineHealth: OFFLINE, ONLINE
NodeHealth:    OFFLINE, PARTIAL, ONLINE
```

- 机器 ONLINE：所有方块 PRESENT，且 `blocks.get(0)` 观测 id == `Node.typeBlockId`。
- 机器 OFFLINE：任一条件不满足。
- 节点 ONLINE：所有机器 ONLINE。
- 节点 PARTIAL：至少一台机器 ONLINE，至少一台 OFFLINE。
- 节点 OFFLINE：没有机器 ONLINE。
- 未探测过的机器/节点按 OFFLINE 处理；用 `probed=false` 在 tooltip 写“未探测”。
- 方块级 `Health` 保留 `UNKNOWN / PRESENT / UNLOADED / MISSING / NO_DIMENSION`，只用于诊断与 tooltip。
- `MachineHealth` / `NodeHealth` 各提供 `describe()`（在线/离线、在线/缺机/离线），供节点终端/机器表/tooltip 共用，避免各处 switch 文案不一致。

### 1.4 IO 规则

- `NodeIoGroup` 归节点；堆叠机器共用一套。
- 规则作用于每台机器的每个方块，不绑定具体方块。
- 只跑 ONLINE 的机器；节点 PARTIAL 时，ONLINE 的机器继续跑。
- 遍历顺序：

```text
for machine in node.machines（起点 = 节点 IO 轮转游标）:
    if machine OFFLINE: continue
    for block in machine.blocks:
        for face in 规则面 / 探测面:
            尝试搬运
```

- 物品规则默认无向；流体/FE 按面；路由表规则不变。
- 失败原因 `OK / NO_ITEM / NO_SPACE / NO_HANDLER / REJECTED` 语义不变；`NO_SPACE` 与 `REJECTED` 不混。
- 路由表按 `BlockKey` 存（每个方块一张），睡眠按机器存。

### 1.5 provider 与余量

- `NodeProvider` 归节点：阻挡、倍率、派单、样板、余量。
- 一个节点一个 `PatternContainer`；样板容量/分组/排序都按节点。
- 一次 `pushPattern` 只选一台 ONLINE 机器；整份货给它。
- 收不下的进**余量队列**（现有 `pending` 语义）：条目 = 资源 + 数量 + 所属机器 id + 上次面；只回填原机器；原机器没了退回 ME 网络；网络也收不下按现有掉落兜底并记日志，不静默丢，也不无界增长（`MAX_PENDING = 64` 硬顶）。
- 不拆分到别的机器。
- 固定倍率：明确 N；N 大于机器容量时多出的进余量。
- 智能倍率：
  - 对每张样板，按“一台机器能装几份”计算 k。
  - 堆叠只支持相同机器，容量一致；代表机器取第一台 ONLINE 即可。
  - **只用 `Actionable.SIMULATE`**，绝不写入机器状态；二分找最大 k；多个输入取最小值；夹在 1..`maxMultiplier` 硬上限。
  - 探测与实际 push 之间机器状态变了：按“已提交”处理，收不下的进余量，不回退成 push 失败（避免 CPU 复制）。
  - 探测失败回退 ×1，tooltip 标“无法估算”。
  - 缓存键 = 样板 + 节点拓扑（机器列表、方块列表、typeBlockId、在线机器集合）；缓存的是**静态上限 kMax**（探测当时的可装份数），不是实时空位。
  - 机器逐渐变满后 kMax 可能偏大：push 收不下的部分进余量，不重新广告、不重复扣料；不做每次 push 重探测。
- 输入和输出同倍；不改变配比。
- 多方块：`ProviderFaceResolver` 对整台机器的所有方块开面，优先 `blocks.get(0)` 类型方块，再逐个部件；阻挡/回收也扫所有方块。
- 派单模式：`SEQUENTIAL` / `ROUND_ROBIN`；新节点默认 `ROUND_ROBIN`。

### 1.6 绑定杖草稿

- 没有服务端会话、没有 TTL。
- 草稿的权威副本是**客户端静态缓存**（按玩家 + 主手槽位）；同一份写入绑定杖的**非 persistent、非 network-synchronized** 物品组件，用于 tooltip 与重开界面恢复。服务端不读组件，只信提交包。
- 登录/登出/换维度/换手/把杖放进容器时清空草稿，保证“不跨登录保留”，也避免客户端栈与服务端栈比较不一致。
- 模式：`SINGLE / STACK / MULTIBLOCK / STACKED_MULTIBLOCK`；蹲下滚轮切换。
- 草稿结构：

```text
BindingDraft
 ├─ mode
 ├─ nodeId（null = 新建节点）
 └─ machines[]
      └─ blocks[]（BlockKey）
```

- 手势：
  - SINGLE：普通左/右键接入/移除单机器节点；蹲下右键提示先切模式。
  - STACK：蹲下右键开草稿/定第一块；右键加机器；蹲下右键空气提交。
  - MULTIBLOCK：蹲下右键定类型方块/开始机器；右键加部件；蹲下右键空气完成并提交。
  - STACKED_MULTIBLOCK：蹲下右键开新机器；右键加部件；蹲下右键空气结束当前机器；当前没有机器时再蹲下右键空气提交整份草稿；动作栏写提示。
  - 取消：蹲下 + 左键空气。
  - 左键方块：从草稿移除该块（客户端撤销）。
- 编辑已有节点：世界蹲下右键已有成员，或节点终端 `+`，把 nodeId 写进草稿；提交时追加。
- 草稿非空不允许切模式。
- 不校验距离；不做防作弊。
- 客户端只做简单核验：主手、重复块、堆叠同 id、目标节点还在最近节点表里。
- 服务端提交按固定事务顺序执行（**占用表是派生快照，不做 reserve/commit**）：
  1. 用 `LinkGate.of(manager)` 取当前占用快照，再用本地 `Set<BlockKey>` 查草稿内部重复；
  2. 全量校验：`LinkGate` 归属、类型、上限、节点归属、方块是否已属于本节点/别的节点；
  3. 在内存里构造候选 `Node`：新建节点，或“已有节点 + 本次新增机器/方块”的浅不可变新实例；已有节点原对象不动；
  4. 全部通过后只调用一次 `NodeLibrary.add` / `NodeLibrary.replace`；索引更新在该方法内原子完成；
  5. `markDirty` 触发 `LinkRegistry.rebuild`；失败/异常时旧 `Node` 与索引保持不变。
- 编辑已有节点时**绝不删除原有机器/方块**；回滚只丢弃候选对象，不碰已存在节点。
- 服务端不接受客户端自报的 nodeId/坐标/归属；全部按玩家工厂与 `LinkGate` 重查。

### 1.7 终端

- **v1 `FactoryScreen`**：废弃兜底，只做字段机械适配，不改设计。
- **v3 `FactoryPassiveIo*`**：机器大卡片改节点大卡片；堆叠节点图标右下角用原版物品数量标识画机器数；节点卡片下编辑节点规则；节点卡片删除 = 删节点；多方块节点先占位（主方块图标 + 方块数 tooltip + 节点规则）。
- v3 按 nodeId 分组后：规则条数取节点规则；速率按成员求和；逐规则原因取最坏（非 OK 优先），不伪造单机器原因。
- 节点终端：provider 三格接真实倍率/派单/阻挡；`+` 接草稿；“编辑中”由客户端读绑定杖草稿判断，不新增服务端会话字段。

### 1.8 config 与硬上限

- 玩法上限全部进 config，默认 `-1` 无上限；注释中英双语。`-1` = 无上限；正数 = 上限；`0` 非法（计数类 0 无法表达“无”，数值类 0 语义也不统一）。
- 配置项与硬上限：

| 配置项 | 默认 | 硬上限（不可关） | 说明 |
|---|---:|---:|---|
| `maxNodes` | -1 | 4096 | 节点数 |
| `maxMachinesPerNode` | -1 | 256 | 单节点机器数 |
| `maxBlocksPerMachine` | -1 | 256 | 单机器方块数 |
| `maxBlocksPerNode` | -1 | 4096 | 单节点方块数 |
| `maxTotalMachines` | -1 | 8192 | 全工厂机器数 |
| `maxTotalBlocks` | -1 | 32768 | 全工厂方块数 |
| `maxRulesPerSide` | -1 | 64 | 每侧规则数 |
| `maxPatternCapacity` | -1 | 1024 | 样板槽 |
| `maxMultiplier` | -1 | 64 | 固定/智能倍率 |
| `maxNameLength` | -1 | 32767 | 名字长度 |
| `observationBlockBudgetPerTick` | 64 | 256 | 观测预算（调优项，不是玩法上限） |
| `staleHealthTicks` | 1200 | 2400 | 健康过期阈值 |

- 有效值 = `min(config, 硬上限)`；config 负数视为“用硬上限”。
- 网络解码固定 `HARD_WIRE_ENTRIES = 32768`（条目/包），注释说明它不是玩法上限；解码用 `min(有效值, HARD_WIRE_ENTRIES)`。
- `MAX_PENDING = 64` 是硬常量，不进 config；余量满了退回 ME 网络，网络也收不下才按现有掉落兜底并记日志，不允许无界增长。
- `ScaledPatternDetails` 的倍率乘法用 `Math.multiplyExact`；溢出/超过硬上限的样板跳过并记日志，不产生负数量。
- config 改小不删已有数据，只阻止新增。
- 协议版本递增；旧档不迁移。

### 1.9 状态归属与运行时定位

- `MachineHealth` / `NodeHealth` 是**派生值**，每次读取由观测快照 + 节点拓扑计算；不存第二份。
- `FactoryLive` 不再保留 `offlineMachines`/`machineMissing` 集合；只保留仓库在线、事件计数等运行时摘要。
- 新增 `factory/probe/BlockObservation` 只读记录（`blockId`、`Health`、`probed`、`lastProbeTick`）；`NodeHealthResolver` / `NodeTypeResolver` 只吃 `Map<BlockKey, BlockObservation>`，**不依赖 `factory.observation`**。
- 新增 `NodeHealthResolver`：纯函数，输入节点 + 方块观测快照，输出 MachineHealth / NodeHealth / probed / stale。
- 新增 `NodeTypeResolver`：纯函数，判断“全离线自动迁移”是否成立。
- **唯一写入点**：`FactoryObservationRunner` 组装 `Map<BlockKey, BlockObservation>`，调用 `NodeTypeResolver`，成立时 `node.withTypeBlockId(newId)`；`Node` 只提供不可变替换方法，不自己做判定。
- `NodeHealthResolver` / `NodeTypeResolver` 签名显式带 `long now, long staleHealthTicks`，不读 `FactoryLimitsConfig`；**纯函数**，不引入 `node → factory` 反向依赖。
- `NodeTypeResolver` 的全离线迁移条件额外要求：所有 `blocks.get(0)` 的 `BlockObservation` **非 stale**；陈旧快照不能参与类型迁移。
- `NodeLibrary` 维护 `byId`、`machineToNode`、`blockToOwner` 三张索引，写 API 只有：
  - `add(Node)`：校验 id/机器/方块唯一与上限，全部通过后一次性写入三张索引；
  - `replace(Node)`：比较旧/新机器的方块差集，先校验冲突与上限，再原子替换索引；
  - `remove(UUID nodeId)`：一次性移除节点及全部机器/方块索引。
  任一方法失败都不改索引，返回结果枚举；不允许调用方直接改内部 map。
- 节点虚拟位置：`NodeRuntime` 用 `anchorLevel` + 由 `nodeId` 两个 64 位半段异或派生的 `BlockPos` 创建 AE2 节点；位置只用于 AE2 身份，不写入存档、不参与 IO。
- 碰撞策略：同一 anchor 维度内派生位置重复时，用 `nodeId + 固定盐` 重哈希重试，最多 8 次；仍冲突则**本次不建**并记一次 ERROR；该节点进入 `COLLISION_RETRY_TICKS = 12000` 退避，退避期内不重复尝试、不重复刷日志。
- `NodeRuntime.matches` 只比较 `factoryId` + `nodeId` + `anchor` + `topologyRevision`；`topologyRevision` 在结构变更（机器/方块/类型）时 +1，名字/规则/阻挡不 +1。
- 结构变化后重建一次 AE2 节点是预期行为；重建前后必须把余量冲刷/保留，不能因重建丢 `pending`。
- 名字/图标刷新：`NodeManager` 对账时即使 `matches=true` 也调用 `NodeRuntime.updateNode(node)`，并让 `NodeTerminalGroup.refreshName()`；改名后 AE2 样板终端不显示旧名。

### 1.10 观测预算与过期

- `observationBlockBudgetPerTick` 由 `FactoryRuntime` 构造时注入 `ObservationService`；`ObservationService` 不直接读 `FactoryLimitsConfig`。
- `FactoryObservationRunner` 负责把方块按优先级排成序列（驱脏 > ONLINE 机器 > 其余），再交给 `ObservationService`；观测层只消费 `BlockKey` 序列，不知道 Node 健康。
- `ObservationService` 只负责探测、存 `lastProbeTick`、吐方块级 `Health`；不判断机器/节点状态。
- 优先级：本 tick 标脏的方块 > ONLINE 机器的方块 > 其余方块轮转；同一台机器的方块尽量连续探测，避免健康长时间一半新一半旧。
- 健康过期：**只在 `NodeHealthResolver` 一处判定**——方块超过 `staleHealthTicks`（默认 1200）没被探测 → stale；机器健康按 OFFLINE 处理，tooltip 写“健康过期”，并把该机器的方块交给观测队列优先复探。
- 这样宁可暂时不跑 IO，也不拿过期健康做搬运判断；大规模工厂由玩家调 budget / config 控制节奏。
- `maxTotalBlocks` 超过观测能力时不会自动删数据；只表现为更新变慢，过期后机器 OFFLINE。

## 4. 存档格式（无迁移）

只写新结构，不读旧结构：

```text
{
  NextSeq: n,                 // 仍是 FactoryStore 根级字段，不属于任何 factory 记录
  Factories: [
    {
      Id, Owner, Anchor, StorageMode,
      Nodes: [
        {
          Id, Name?, TypeBlockId,
          Io: { Inputs, Outputs },
          Provider: {
            Blocking, Mode, ModePinned,
            MultiplierMode, MultiplierFactor, Dispatch,
            Capacity, Patterns,
            Pending: [ { Key, Amount, MachineId, Face } ]
          },
          Machines: [
            { Id, Blocks: [ { Dimension, Pos }, ... ] }
          ]
        }
      ]
    }
  ]
}
```

方块存储：

- `BlockKey` 含维度 + 坐标；每个方块写 `Dimension` + `Pos`，**不要**写成“一个维度 + 坐标列表”。
- 因为同一台机器可跨维度，每台机器写 `Blocks: [ { Dimension, Pos }, ... ]`，不存机器维度。
- 机器 id / 节点 id 是随机 UUID，和方块 key 没有派生关系；读取只校验 id 唯一、方块不重复、类型方块存在、机器/节点上限。
- `Node.TypeBlockId` 必须存在；所有机器的 `blocks.get(0)` id 必须等于它（除非刚完成自动迁移，写回新值）。
- `NextSeq` 必须保留在 `FactoryStore` 根级，**不进入 factory 记录**；`FactoryLifecycleService` 用它生成确定性工厂 id；重构只替换 `Machines → Nodes`，其余根键不动。
- 旧档不读；旧测试世界加载为空是预期行为，重建测试世界。

失败处理：

- 坏机器：丢弃该机器并 warn；节点无机器则丢弃节点。
- 坏方块：丢弃该方块；机器无方块则丢弃机器。
- 超限：config 无上限时按硬上限处理；网络解码受 `HARD_WIRE_ENTRIES`。
- 重复 id / 重复方块：保留先登记，丢弃后登记并 warn。

### 7.1 数据与健康

1. 连续加/删同一节点的机器：每次结构变化最多重建一次；规则/名字/阻挡等非结构变化不重建；重建前后 `pending` 不丢。
2. 重启后同一节点仍用同一虚拟位置；不因机器掉线而漂移；人为制造位置碰撞时按固定盐重试，仍冲突则不建节点并报一次 ERROR，退避 12000 tick 内不重复刷日志。
3. 绑定提交失败后重试同一草稿能成功；失败不产生 `LinkRegistry` 占用，也不改旧节点。
4. 工厂删除/节点删除后 `LinkRegistry` 无残留占用；`NodeLibrary` 无孤儿机器。
5. `NextSeq` 在保存/重载/删工厂后不回退，工厂 id 稳定。

## 8. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 旧档不迁移 | 旧测试世界加载为空 | 明确预期；重建测试世界；不写迁移兼容层 |
| P1b 切换提交过大 | 不能单独 revert 数据模型 | P1a 只新增、P1c 只清理；P1b 是唯一不可单独回滚的切换，提交前后都做 build+1:1 冒烟 |
| 随机 id 后命令/定位全变 | 旧短 id 失效 | 开发期可接受；文档/测试按新 id |
| 节点跨维度 | provider/余量落料位置复杂 | 余量绑定原机器；原机器没了退网络；虚拟节点用 nodeId 派生固定位置 |
| 虚拟节点位置碰撞 | AE2 节点可能冲突 | 位置由 nodeId 派生；重试 8 次仍冲突则跳过并 ERROR，退避 12000 tick 不刷日志 |
| 无 config 上限 | 大规模数据卡顿/OOM | 硬上限表；`HARD_WIRE_ENTRIES`；观测预算/过期；config 只能调低 |
| 倍率溢出 | 数量变负数/复制 | `Math.multiplyExact` + 硬上限；溢出跳过并记日志 |
| 观测过期 | 健康停在旧值，IO 误判 | 默认 64/tick；`staleHealthTicks` 后机器 OFFLINE 并优先复探 |
| 绑定事务不原子 | 节点/占用残留 | 校验→候选 Node→原子 add/replace；失败只丢候选，旧节点与索引不动 |
| 客户端草稿丢失 | 退出重进/丢杖丢草稿 | 已确认不跨登录；组件非 persistent、非网络同步；登录/换维度/换手清空 |
| 智能倍率容量探测 | 每次重建可能贵；探测失败 | 只用 SIMULATE；缓存按样板+拓扑；失败 ×1 |
| provider 多方块开面 | 面选择/阻挡/回收复杂度上升 | 统一 `Faces` 按机器收集所有方块；每方块缓存 |
| v1 兜底编译适配 | 旧界面语义与新节点模型不完全一致 | 只做机械适配；规则动作按 nodeId；不改设计 |
| 协议三次变更 | 联调困难 | P1b 27 / P6 28 / P7 29；每次与包结构同提交 |
| AGENTS/ADR 滞后 | 代码与旧约束冲突 | P1b 同提交 ADR-034/035；ADR-032 标 superseded；AGENTS 修订提案留待批准 |
| 批量替换损坏中文 | 注释乱码 | 只用 bash；替换后 `git diff` 全量检查；损坏回退 |

回滚：

- P1a、P1c 可单独 `git revert`；**P1b 不可单独回滚**，要回滚必须 P1a+P1b+P1c 一起退回。
- 无旧档迁移，所以没有“迁移后回不去”的数据风险；旧测试世界重建即可。
- 协议在 P1b/P6/P7 三次变化；回滚对应阶段时客户端/服务端一起回退。
- 回滚后重新 `.\gradlew.bat build`。
