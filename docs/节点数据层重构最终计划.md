# 节点数据层重构最终计划

> 状态：待执行
> 最后更新：2026-11-04
> 依据：[15-节点数据层重构确认](草稿纸/15-节点数据层重构确认.md)
> 目标：把“1 机器 = 1 节点 = 1 方块”改成“节点 → 机器 → 方块”，并完成节点级 IO、provider、绑定杖草稿、v3 IO 终端节点卡片与相关指令/诊断。
> 非目标：不改玩法数值、不改美术语言、不新增资源类型、不为旧档写迁移、不改 `AGENTS.md`。

---

## 0. 最终结论摘要

- 三层：**节点 → 机器 → 方块**。
- 节点 id、机器 id 都是随机 UUID；方块 key 只表示位置，不派生任何 id。
- 节点、机器都不存维度；维度在方块上。节点内机器可跨维度；同一台机器内部方块也可跨维度；任何方块不可用 → 整台机器 OFFLINE。
- 节点类型只认**主方块 id**：单方块机器看唯一方块，多方块机器看主方块；部件不参与类型判定。
- 节点内所有机器必须同一种主方块 id；部分机器掉线时，原地出现不同方块不认；所有机器都掉线且主方块统一变成另一个 id 时，节点自动迁移类型。
- `MachineHealth` 只有 ONLINE/OFFLINE；`NodeHealth` 只有 ONLINE/PARTIAL/OFFLINE；方块级 `Health` 仅用于诊断。
- IO 规则归节点；堆叠机器共用一套；只跑 ONLINE 的机器。
- provider 归节点；一个节点一个 `PatternContainer`；一次货只给一台机器；收不下进余量队列，余量条目绑定原机器，不拆分。
- 智能倍率按“一台机器能装几份”算；探测失败回退 ×1；输入输出同倍。
- 多方块 provider 对整台机器的所有方块开面，优先主方块，再逐个部件；阻挡/回收也扫所有方块。
- 绑定杖使用**客户端草稿物品组件 + 完成时一次提交**；无服务端会话、无时间限制、不校验距离；草稿不跨登录保留。
- v1 `FactoryScreen` 是废弃兜底，只做编译机械适配；v3 `FactoryPassiveIo*` 改成节点大卡片。
- 所有上限进 config，默认 `-1` 无上限；网络解码保留固定安全硬上限；旧档不迁移。

## 1. 目标模型

### 1.1 三层与不变量

```text
Node
 ├─ id: UUID（随机）
 ├─ name: String / null
 ├─ typeBlockId: ResourceLocation   // 节点类型 = 主方块 id
 ├─ io: NodeIoGroup
 ├─ provider: NodeProvider
 └─ machines: List<Machine>          // 加入顺序稳定，不按坐标/状态重排
      └─ Machine
           ├─ id: UUID（随机）
           └─ blocks: List<BlockKey> // 每块自带维度；第 0 块是主方块
```

不变量：

1. 节点至少 1 台机器；机器至少 1 个方块。
2. 同一台机器的所有方块不要求同维度；任一block不可用 → 机器 OFFLINE。
3. 节点内所有机器的主方块 id 必须等于 `Node.typeBlockId`；例外只有“全离线自动迁移”。
4. 单方块机器没有“主方块”概念，类型用唯一方块；多方块机器 `blocks.get(0)` 是主方块。
5. 节点 id、机器 id 随机生成；加/删方块、换主方块不改机器 id。
6. 方块全局唯一：一个 `BlockKey` 只能属于一个节点的一台机器。
7. 机器列表顺序 = 加入顺序；不按坐标或状态重排。
8. 运行时游标（派单/IO 轮转）只存内存，不写档。

### 1.2 身份与类型

- **节点 id**：随机 UUID；1:1 时不再等于机器 id。
- **机器 id**：随机 UUID；不再由方块 key 派生。
- **BlockKey**：`(dimension, pos)`，只用于观测、占用、路由、定位。
- **节点类型**：`Node.typeBlockId` 持久化。
  - 单方块机器：该方块 id。
  - 多方块机器：主方块 id。
  - 部件（输入输出总线、外壳等）不参与类型判定。
- **自动迁移**：
  - 只要还有机器 ONLINE，缺失机器原地出现不同方块 → 不认，保持 missing。
  - 当节点所有机器都 OFFLINE，且所有机器的主方块都观测为 PRESENT、blockId 非空、且都是**同一个新 id**、且不等于当前 `typeBlockId` → 更新 `typeBlockId`，节点迁移类型；节点 id、规则、样板、名字、机器 id 全部保留。
  - 部分换、类型不一致、主方块空气/未加载 → 不迁移。
  - 单机器节点同样适用：唯一机器掉线且被换成另一类机器时，节点认新类型。

### 1.2.1 视图字段（节点/机器可能跨维度）

- `NodeView`：`nodeId`、`name`、`typeBlockId`、`health`（NodeHealth）、`machineCount`、`onlineMachineCount`、`blockCount`、`ruleCount`、`patternCount`、`provider`、`members`；**去掉 `machineMissing`**，健康统一由 `health` 表达。
- `MemberView`：`machineId`、`blocks: List<BlockKey>`、`blockId`（主方块观测 id）、`health`（MachineHealth）；**不再有单一 `dimension` 字段**；需要主方块时用 `mainBlock()`。
- `MachineView`（v1/v3 机器表）：`nodeId`、`nodeName`、`nodeIconBlockId`、`nodeMachineCount`、`machineId`、`primaryBlock`（维度 + 坐标）、`blockCount`、`health`（MachineHealth）、规则字段；v3 按 `nodeId` 分组，图标用 `nodeIconBlockId`，数量用 `nodeMachineCount`。
- 协议里 `MemberView` 的每个方块都要写“维度 + 坐标”，不能只写一个维度再跟坐标列表。

### 1.3 健康

```text
MachineHealth: OFFLINE, ONLINE
NodeHealth:    OFFLINE, PARTIAL, ONLINE
```

- 机器 ONLINE：所有方块 PRESENT，且主方块观测 id == `Node.typeBlockId`。
- 机器 OFFLINE：任一条件不满足。
- 节点 ONLINE：所有机器 ONLINE。
- 节点 PARTIAL：至少一台机器 ONLINE，至少一台 OFFLINE。
- 节点 OFFLINE：没有机器 ONLINE。
- 未探测过的机器/节点按 OFFLINE 处理；tooltip 写“未探测”。
- 方块级 `Health` 保留 `UNKNOWN / PRESENT / UNLOADED / MISSING / NO_DIMENSION`，只用于诊断与 tooltip。

### 1.4 IO 规则

- `NodeIoGroup` 归节点；堆叠机器共用一套。
- 规则作用于每台机器的每个方块，不绑定具体方块。
- 只跑 ONLINE 的机器；节点 PARTIAL 时，ONLINE 的机器继续跑。
- 遍历顺序：

```text
for machine in node.machines（起点 = 节点 IO 轮转游标）:
    if machine OFFLINE: continue
    for block in machine.blocks:
        for face in 规则面 / 探测面:
            尝试搬运
```

- 物品规则默认无向；流体/FE 按面；路由表规则不变。
- 失败原因 `OK / NO_ITEM / NO_SPACE / NO_HANDLER / REJECTED` 语义不变；`NO_SPACE` 与 `REJECTED` 不混。
- 路由表按 `BlockKey` 存（每个方块一张），睡眠按机器存。

### 1.5 provider 与余量

- `NodeProvider` 归节点：阻挡、倍率、派单、样板、余量。
- 一个节点一个 `PatternContainer`；样板容量/分组/排序都按节点。
- 一次 `pushPattern` 只选一台 ONLINE 机器；整份货给它。
- 收不下的进**余量队列**（现有 `pending` 语义）：条目 = 资源 + 数量 + 所属机器 id + 上次面；只回填原机器；原机器没了退回 ME 网络；网络也收不下就保留/记日志，不静默丢。
- 不拆分到别的机器。
- 固定倍率：明确 N；N 大于机器容量时多出的进余量。
- 智能倍率：
  - 对每张样板，按“一台机器能装几份”计算 k。
  - 堆叠只支持相同机器，容量一致；代表机器取第一台 ONLINE 即可。
  - 用 `PatternProviderTarget` 模拟插入，二分找最大 k；多个输入取最小值；夹在 1..config 上限。
  - 探测失败回退 ×1，tooltip 标“无法估算”。
  - 缓存按“样板 + 节点拓扑”失效重建。
- 输入和输出同倍；不改变配比。
- 多方块：`ProviderFaceResolver` 对整台机器的所有方块开面，优先主方块，再逐个部件；阻挡/回收也扫所有方块。
- 派单模式：`SEQUENTIAL` / `ROUND_ROBIN`；新节点默认 `ROUND_ROBIN`。

### 1.6 绑定杖草稿

- 没有服务端会话、没有 TTL。
- 草稿存在绑定杖物品组件（客户端）；完成时一次提交，服务端全量校验后原子应用。
- 草稿不跨登录保留；退出重进丢失可接受。
- 模式：`SINGLE / STACK / MULTIBLOCK / STACKED_MULTIBLOCK`；蹲下滚轮切换。
- 草稿结构：

```text
BindingDraft
 ├─ mode
 ├─ nodeId（null = 新建节点）
 └─ machines[]
      └─ blocks[]（BlockKey）
```

- 手势：
  - SINGLE：普通左/右键接入/移除单机器节点；蹲下右键提示先切模式。
  - STACK：蹲下右键开草稿/定第一块；右键加机器；蹲下右键空气提交。
  - MULTIBLOCK：蹲下右键定主方块/开始机器；右键加部件；蹲下右键空气完成并提交。
  - STACKED_MULTIBLOCK：蹲下右键开新机器；右键加部件；蹲下右键空气结束当前机器；当前没有机器时再蹲下右键空气提交整份草稿；动作栏写提示。
  - 取消：蹲下 + 左键空气。
  - 左键方块：从草稿移除该块（客户端撤销）。
- 编辑已有节点：世界蹲下右键已有成员，或节点终端 `+`，把 nodeId 写进草稿；提交时追加。
- 草稿非空不允许切模式。
- 不校验距离；不做防作弊。
- 客户端只做简单核验：主手、重复块、堆叠同 id、目标节点还在最近节点表里。
- 服务端提交时逐块重校验，全过才应用；任何一块失败整份拒绝。

### 1.7 终端

- **v1 `FactoryScreen`**：废弃兜底，只做字段机械适配，不改设计。
- **v3 `FactoryPassiveIo*`**：机器大卡片改节点大卡片；堆叠节点图标右下角用原版物品数量标识画机器数；节点卡片下编辑节点规则；节点卡片删除 = 删节点；多方块节点先占位（主方块图标 + 方块数 tooltip + 节点规则）。
- v3 按 nodeId 分组后：规则条数取节点规则；速率按成员求和；逐规则原因取最坏（非 OK 优先），不伪造单机器原因。
- 节点终端：provider 三格接真实倍率/派单/阻挡；`+` 接草稿；“编辑中”由客户端读绑定杖草稿判断，不新增服务端会话字段。

### 1.8 config 与协议

- 上限全部进 config，默认 `-1` 无上限；注释中英双语。
- 配置项：`maxNodes`、`maxMachinesPerNode`、`maxBlocksPerMachine`、`maxBlocksPerNode`、`maxTotalMachines`、`maxTotalBlocks`、`maxRulesPerSide`、`maxPatternCapacity`、`maxMultiplier`、`maxNameLength`。
- `-1` = 无上限；`0` = 禁止新增（保留给“全关”场景）；正数 = 上限。
- 名字长度无上限时，解码侧仍用 `32767` 硬顶（`readUtf` 上限），避免无界字符串。
- 网络解码保留固定安全硬上限 `WIRE_HARD_LIMIT = 1_000_000`（条目/包），注释说明不是玩法上限；解码用 `min(config, WIRE_HARD_LIMIT)`，config 负数视为无上限。
- config 改小不删已有数据，只阻止新增。
- 协议版本递增；旧档不迁移。

## 2. 包结构与依赖方向

不新建顶层包；`BindingService`、`NodeActions` 等留在 `factory` 根包（编排层）。

```text
factory/location       BlockKey
factory/machine        Machine、ResourceSpec、MatchMode
factory/probe          Health（方块级）、MachineHealth、NodeHealth、BlockProbe、WorkState
factory/node           Node、NodeLibrary、NodeLibraryView、NodeIoGroup、NodeProvider、
                       Multiplier、MultiplierMode、DispatchMode、ProviderMode、BlockingMode
                       + MachineNode / NodeManager / provider 运行时
factory/io             NodeIoRunner、MachineIoRunner、RuleResolver、IoTransfer、RunnerState...
factory                Factory、FactoryConfig、FactoryStore、FactoryManager、FactoryRuntime、
                       FactoryService、NodeService、NodeActions、NodeLibraryService、
                       BindingService、BindingDraft、BindingMode、FactorySnapshotBuilder、
                       FactoryNodeSnapshotBuilder、FactoryNodeRunner、FactoryObservationRunner、
                       FactoryTickRunner、LinkRegistry、LinkGate、FactoryLimitsConfig...
network/payload        编解码与边界校验
client / client.screen UI 与客户端草稿
```

依赖方向：

- `factory.machine` 不依赖 `factory.node`。
- `factory.node` 依赖 `factory.machine`、`factory.location`、`factory.probe`。
- `factory.io` 依赖 `factory.node`、`factory.machine`、`factory.observation`、`factory.capability`、`factory.storage`。
- `factory` 依赖以上全部。
- `network` 依赖 `factory` 与视图；`client` 依赖 `network` 与视图。
- 不新增反向边；`factory.node` 运行时继续直接用 AE2 API（现状如此）。

## 4. 存档格式（无迁移）

只写新结构，不读旧结构：

```text
Factories: [
  {
    Id, Owner, Anchor, StorageMode,
    Nodes: [
      {
        Id, Name?, TypeBlockId,
        Io: { Inputs, Outputs },
        Provider: {
          Blocking, Mode, ModePinned,
          MultiplierMode, MultiplierFactor, Dispatch,
          Capacity, Patterns, Pending
        },
        Machines: [
          { Id, Blocks: [ { Dimension, Pos }, ... ] }
        ]
      }
    ]
  }
]
```

方块存储：

- `BlockKey` 含维度 + 坐标；存档里每个方块写 `Dimension` + `Pos`，或写统一维度 + 坐标列表。
- 因为同一台机器可跨维度，建议每台机器写 `Blocks: [ { Dimension, Pos }, ... ]`，不存机器维度。
- 读取时不校验机器 id 与方块 key 的派生关系；只校验 id 唯一、方块不重复、主方块存在、机器/节点上限。
- `Node.TypeBlockId` 必须存在；所有机器主方块 id 必须等于它（除非刚完成自动迁移，写回新值）。
- 旧档不读；旧测试世界加载为空是预期行为，重建测试世界。

失败处理：

- 坏机器：丢弃该机器并 warn；节点无机器则丢弃节点。
- 坏方块：丢弃该方块；机器无方块则丢弃机器。
- 超限：config 无上限时不截断；网络解码仍受 `WIRE_HARD_LIMIT`。
- 重复 id / 重复方块：保留先登记，丢弃后登记并 warn。

## 8. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 旧档不迁移 | 旧测试世界加载为空 | 明确预期；重建测试世界；不写迁移兼容层 |
| 随机 id 后命令/定位全变 | 旧短 id 失效 | 开发期可接受；文档/测试按新 id |
| 节点跨维度 | provider/余量落料位置复杂 | 余量绑定原机器；原机器没了退网络；虚拟节点位置用第一台在线机器/锚点 |
| 无 config 上限 | 大规模数据卡顿/OOM | 网络硬上限；观测/IO 预算；config 可手动限制 |
| 智能倍率容量探测 | 每次重建可能贵；探测失败 | 缓存；只在拓扑/样板变化时重算；失败 ×1 |
| provider 多方块开面 | 面选择/阻挡/回收复杂度上升 | 统一 `Faces` 按机器收集所有方块；每方块缓存 |
| 客户端草稿丢失 | 退出重进/丢杖丢草稿 | 已确认不跨登录；动作栏提示“完成后提交” |
| v1 兜底编译适配 | 旧界面语义与新节点模型不完全一致 | 只做机械适配；规则动作按 nodeId；不改设计 |
| 协议一次改太多 | 联调困难 | P6 拆子提交；每步 build；版本号最后一次统一 |
| 批量替换损坏中文 | 注释乱码 | 只用 bash；替换后 `git diff` 全量检查；损坏回退 |

回滚：

- 每阶段独立提交，`git revert` 该阶段即可。
- 无旧档迁移，所以没有“迁移后回不去”的数据风险；旧测试世界重建即可。
- 协议改动集中在 P6/P7；回滚后旧客户端/旧服务端一起回退。
- 回滚后重新 `.\gradlew.bat build`。
