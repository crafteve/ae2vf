## 0. 定位

### 0.1 它是什么

一句话：**虚拟 pattern provider + 全局仓库**。

AE2 的自动合成已经很接近放置游戏：写样板、下订单、CPU 递归展开、机器执行。唯一破坏体验的是「把机器接进 AE」这一步——要摆接口方块、要布线、要在同一个网络里。

本模组把这一步虚拟化：

- pattern 不再绑在接口方块上，而是**直接绑在机器上**
- 产物不经过管道，直接进**全局仓库**
- 接入机器是一个逻辑动作（终端右键），不是物理布线

### 0.2 它不是什么

- **不是自动读配方**。配方永远由玩家提供。自动读配方在科技整合包里必然卡在条件配方、多输出、副产物、自定义配方类型上。
- **不是重造 AE2**。存储、样板、CPU 这些概念是 AE2 的，本模组只是把它们的「执行端」从接口方块换成机器。
- **不是机器间直连的物流网络**。机器之间不连线，所有交换都经过仓库。

### 0.3 核心用户

硬核科技整合包玩家：不怕机器慢，怕手动搭；对重复劳动容忍度极低。产品取向是效率工具，不是新手引导。

## 1. 设计原则

### P1 配方由玩家提供

模组不推断配方、不反查配方。pattern 和被动模式的输入输出清单，都由玩家显式配置。

### P2 只虚拟化搬运

物品 / 流体 / 能量 / 化学品从机器到仓库、从仓库到机器，这一层虚拟化。机器内部的加工、配方、能量需求、时间，一律不动。

### P3 能力可选

Core 不假设某种资源类型一定存在。`IWarehouse.supports(type)` 由后端回答。1.21.1 支持四种资源，1.7.10 支持两种。

### P4 默认安全

后端失败、适配失败、维度失败，都降级不崩溃。

## 2. 系统结构

```
┌─────────────────────────────────────────────────┐
│ UI 层：终端                                       │
│   库存 / 机器列表 / 被动配置 / pattern / CPU      │
├─────────────────────────────────────────────────┤
│ 编排层                                            │
│   主动：CPU（递归展开、派工、reserved）            │
│   被动：补料器（按清单补、按清单抽）               │
├─────────────────────────────────────────────────┤
│ 接入层                                            │
│   机器 ↔ 仓库 的 IO                               │
│   区块加载 / 权限                                 │
├─────────────────────────────────────────────────┤
│ 存储层  IWarehouse（抽象）                        │
│   ├─ 自建后端（默认）                             │
│   └─ AE2 后端（可选）                             │
├─────────────────────────────────────────────────┤
│ MC 适配层                                         │
│   Capability / Level / BlockEntity / 网络包       │
└─────────────────────────────────────────────────┘
```

依赖方向严格向下。Core（存储抽象 + 编排逻辑）不 import 任何 Minecraft 类，可在无头环境单测。

## 3. 仓库

### 3.1 全局抽象，没有方块

仓库不属于任何维度，没有实体方块。玩家通过终端访问。

推论：

- 跨维度免费
- 没有「仓库被破坏 / 被偷」的问题
- 容量和吞吐是**账户属性**，不是方块属性

### 3.2 归属

每个玩家一个仓库账户，可组队共享（队伍成员共用一份）。

- 单人：一份账户
- 组队：队伍共享一份，成员有读写权
- 未组队：各自独立，不能互相存取

### 3.3 资源类型

| 版本 | 物品 | 流体 | 能量（FE） | 化学品 |
|---|---|---|---|---|
| 1.21.1 | ✓ | ✓ | ✓ | ✓ |
| 1.7.10 | ✓ | ✓ | ✗ | ✗ |

**能量只认 FE**（NeoForge 标准）。EU、Joule 等其他能量单位不在支持列表里——GTCEu 等机器要送电，仍然用真实线缆。这不是遗漏，是有意的边界：FE 是 1.21.1 的事实标准，其他单位没有统一换算率。

**化学品**指 Mekanism 那类资源：gas、infusion、pigment、slurry 等。它们不是流体，有自己的 registry，所以必须作为独立类型处理。具体有哪些子类型，取决于整合包装了什么模组——没装 Mekanism 就没有 gas。

`ResourceType` 是 `(kind, subtype)`：

- `ITEM`：无 subtype
- `FLUID`：无 subtype
- `ENERGY`：subtype 固定为 `fe`
- `CHEMICAL`：subtype 是化学品类型（`gas` / `infusion` / `pigment` / `slurry` …），由装载的模组注册

### 3.4 容量与吞吐

- **容量**：每种资源有独立上限。到上限后，向该资源的供料停止（见 3.6）。
- **吞吐**：每秒可搬运的总量，是仓库属性，不是「每条连接」的属性。

### 3.5 升级

没有方块，升级靠**消耗资源提升账户等级**。等级影响：容量、吞吐、可接入机器数。

具体数值 TBD。

### 3.6 停机规则

被动模式会持续生产，产物可能无限堆积。仓库必须能停机：

- 某资源到容量上限 → 停止向该资源供料
- 或者玩家设置「目标存量」→ 达到就停

具体策略 TBD，但必须存在，否则挂机会塞爆。

## 4. 接入

### 4.1 终端

一个**无线物品**，不占方块位。右键打开界面。获取方式 TBD（开局给一个 / 合成 / 其他）。

### 4.1.1 绑定方式（暂定）

绑定载体是 AE2 的**量子纠缠奇点**。它本身就带一个 `long` 频率（`AEComponents.ENTANGLED_SINGULARITY_ID`），不需要我们扩展。

流程：

1. ME 网络侧建一个量子环，环里放一个奇点（频率 F）
2. 终端 GUI 的绑定槽里放一个**同频**的奇点
3. 终端读 F，用 `Locatables.quantumNetworkBridges().get(serverLevel, F)` 全局查到 `QuantumCluster`
4. `QuantumCluster.getActionableNode().getGrid()` → 拿到 `IGrid`
5. 拔掉奇点 = 解除绑定

为什么能跨维度：`Locatables.quantumNetworkBridges()` 内部是一个**全局 `HashMap<Long, IActionHost>`**，不按维度分区；`get(Level, long)` 的 `Level` 参数只用来确保调用发生在服务端，不参与匹配。

前提条件：

- 量子环必须**已成型且有电**
- **两个环都要放奇点**、且频率相同（AE2 的配对是 `+F` 和 `-F` 互相注册）
- 环所在区块必须加载，否则 `QuantumCluster` 会注销

待验证：

- 服务器重启后环的注册时机
- 环区块未加载时的降级提示
- 玩家只有单个奇点（没有配对）时的行为

### 4.2 接入动作

手持终端右键机器 → 该机器登记进仓库。

- 机器必须在玩家的权限范围内
- 接入后，模组负责它的 IO 和区块加载
- 可以随时取消接入

### 4.3 区块加载

接入的机器所在 chunk 强制加载。取消接入时释放。

### 4.4 权限

- 仓库账户的拥有者可以接入 / 取消 / 配置
- 队伍成员共享这些权限
- 非成员不能接入别人的机器

多人冲突（两人同时配置同一台机器）TBD。

## 5. 被动模式

### 5.1 配置

玩家手动填写每台机器的：

- **输入清单**：从仓库取哪些资源、多少
- **输出清单**：哪些资源进仓库

不需要读配方。玩家看到机器在做什么，就填什么。

### 5.2 批量复制

单台填写太慢，提供两种批量方式：

- **配置器**：手持物品，右键机器 A 复制配置，右键机器 B 粘贴。适合逐台刷。
- **蓝图**：保存一组机器的配置，可以整体应用到另一组机器。适合整片复制。

两者的边界与形态 TBD。

### 5.3 补料与抽取

每 tick：

1. 对每台被动机器，检查输入槽缺什么，从仓库取，insert
2. 检查输出槽有什么，从机器 extract，进仓库

搬运量受仓库吞吐限制。

### 5.4 库存上限

见 3.6。到上限停止供料，机器自然停。

## 6. 主动模式

### 6.1 pattern

玩家在终端里给机器写 pattern：

- 输入：一组 `(ResourceType, amount)`
- 输出：一组 `(ResourceType, amount)`
- 绑定到一台机器

这和 AE2 的 processing pattern 语义一致，区别是绑定对象是机器，不是接口方块。

### 6.2 CPU

玩家在终端里下单：目标产物 + 数量。CPU：

1. 递归展开 pattern 树
2. 展开时查仓库库存 + 正在生产中的量（reserved）
3. 派任务给能执行对应 pattern 的机器
4. 机器从仓库取料、加工、产物进仓库
5. 所有中间产物到齐，订单完成

### 6.3 与 AE2 的关系

- 装了 AE2：AE2 可以作为仓库的**存储后端**，ME 网络里的物品对 Idle Factory 可见
- 本模组的 CPU 和 AE2 的 CPU 是两套，并存
- 是否复用 AE2 的 pattern 物品、两套 CPU 是否互通：TBD

### 6.4 竞态

CPU 展开时，必须把「已下单但未完成」的量算进去，否则会重复下单。对应 AE2 的 reserved amount。

实现：每个 pattern 有一个 `reserved` 计数，下单时增加，完成时减少。

### 6.5 模式边界

**每台机器二选一**：被动或主动。

理由：被动持续吃料、主动按单吃料，同一台机器混着来会退化成优先级问题。

此条待确认。

## 7. 版本差异

### 7.1 1.21.1

- 四种资源：物品、流体、能量（FE）、化学品
- 能量无损（见 ADR-006）
- 物品接口：`IItemHandler`
- 能量接口：`IEnergyStorage`（FE）
- 化学品接口：Mekanism 的 `IChemicalHandler` 等，逐模组适配
- 维度注册：datapack JSON（如果做工厂维度）

### 7.2 1.7.10

- 两种资源：物品、流体
- 能量必须走真实线缆
- 化学品不支持
- 物品接口：`IInventory`
- 能量接口：GT 的 `IEnergyContainer` 等，不统一
- 维度注册：代码 `WorldProvider`

### 7.3 Core 抽象

Core 必须能表达「能力可选」：

```java
interface IWarehouse {
    boolean supports(ResourceType type);
    long amount(ResourceType type);
    long capacity(ResourceType type);
    long insert(ResourceType type, long amount, boolean simulate);
    long extract(ResourceType type, long amount, boolean simulate);
}
```

后端声明自己支持哪些。1.7.10 的后端对 `ENERGY`、`CHEMICAL` 返回 `false`。

Core 锁 Java 8 语言级别，保证两版共用。
