- 已知例外（本轮保留）：payload.handle 直接调 client.network.Client*Handler，形成 network ↔ client；重启条件是「客户端 handler 注册移出 payload」。

### 阶段 2 · 观测层重写 + 能力收口（协议 38）

- ObservationTable：Map<BlockKey, Entry> + ArrayList<Entry>；Entry 原地改、不替换；API 只有 reconcile(Set<BlockKey>)、remove(key)、contains、标量读；表内维护 chunk → keys 索引。
- reconcile = 补缺失并标 due + 删多余；游标在批量删除时按叠加算法修正（删在游标前计 d → 减 d；游标行被删 → 不前进；越过表尾 → 归零）；空表、单行、删到空有保护。
- ObservationRunner：结构 → 内容 → 健康/工态两条游标；三条通道（健康 / 工态 / 事件）各默认 128（下限 1，不设硬上限）；间隔 120 / 120→1200（健康）、5 / 40 / 120→1200（工态）；读档首 tick 一次 reconcile，之后每 1200 tick；变化只走 ObservationChange 批量广播。

## 3. 行为变化清单（需签字）

1. 仓库只剩 ME，容器整线删除，旧档不迁。
2. 机器判定改「方块实体 + 任一能力 / 原版 Container」，只在绑定查；之后能力丢失仍显示在线，只是不搬。
3. 健康分三层：方块「在不在」/ 机器「含类型」/ 节点「按在线台数分档」；类型不一致不再算方块不健康。
4. 观测调度换两条队列 + 两条游标；健康 / 工态 / 事件三条通道各默认 128（下限 1，不设硬上限）；间隔 120 / 120→1200（健康）与 5 / 40 / 120→1200（工态）；读档首 tick 对账、之后每 1200 tick。
5. 观测表原地改行、reconcile 补行删行、表内维护 chunk 索引、变化只走 ObservationChange。
6. 写协议收成一对；Gate 唯一校验；Apply 只改内存；删除守卫按 kind 分级；自动 FE 规则改 SYSTEM 命令（绑定成功后补一条，失败只记日志、不影响提交）；世界命令用 containerId = -1 跳过会话步骤。
7. 工厂 id 用 owner 派生，删 FactoryStore.nextSeq（客户端 WandCoordinator.nextSeq 不动）；Entry 只写 Owner。
8. 落盘两条路径：配置行 put + 运行时 flush；两者都整体重建 Entry，put 记录本 tick 已写、flush 跳过，同工厂同 tick 最多一次；停服 flushAll → save → 拆节点；不再每 tick 整表重写。
