# UI · P0：把底图放进游戏

> 状态：已落地（可进游戏查看）
> 关联：[GUI.md](../GUI.md)、[mockup-v2.png](mockup-v2.png)

## 0. 为什么先做 P0

在写任何数据同步之前，有两个问题必须先量出来，否则后面全是返工：

1. **面板占屏比例**：781×480 是算出来的，真实观感只有进游戏才知道
2. **配方查看器要留多宽**：JEI/EMI/REI 在客户端左右两侧各占一块，猜不准

这两件事用一张底图就能回答，成本不到一百行代码。所以 P0 只做「能看」，不做「能用」。

## 1. 边界

**做**：可拉伸的面板底图、`/idf gui` 开屏、真实字体画的假数据、可现场调的留白常量。

**不做**：数据同步、交互、动画、真实规则编辑。

界面上除了关闭按钮，什么都点不动——这是刻意的，点了会动会让人误以为已经接上数据。

## 2. 怎么试

```
/idf gui
```

面板按屏幕居中。留白（每侧给配方查看器的宽度）默认 **48**，可以现场改：

```
-Didlefactory.gutter=64
```

加到 JVM 参数里（开发环境改 `build.gradle` 的 `runs.client.jvmArguments`，或直接在 IDE 的
运行配置里加）。改完重开游戏即可，不用重新编译。

**怎么判断留白够不够**：打开面板，看 JEI 的原料列表有没有压到面板边框上；压到了就把 gutter 调大。

## 3. 尺寸

| 量 | 值 | 备注 |
|---|---|---|
| 设计目标画布 | 853 × 480 | 2560×1440 @ GUI Scale 3 |
| 面板 | 757 × 480 | 屏宽 − 2×gutter，满高 |
| 左区（机器表） | 549 宽 | 吸收剩余宽度 |
| 右区（仓库/机器） | 196 宽 | **固定**，不随窗口变 |
| 行高 | 26 | 含 1px 分隔线 |
| 格子 | 18 | 合成格 20，结果格 22 |

右区固定宽度是刻意的：以后换分辨率只让左表变宽变窄，右区的几何常量一个都不用动。

## 4. 贴图从哪来

**不是手画的。** 静态外观由脚本离线生成：

```
python tools/gui/gen_textures.py
  → src/main/resources/assets/idlefactory/textures/gui/*.png
```

| 贴图 | 尺寸 | 用法 |
|---|---|---|
| `panel.png` | 10×10，边框 3 | 面板底：外深、内亮、一层内凹斜边 |
| `slot.png` | 4×4，边框 1 | 凹槽格子，可拉伸到任意大小 |
| `button.png` | 6×6，边框 1 | 凸起按钮 |
| `field.png` | 4×4，边框 1 | 输入框 |
| `divider*.png` `header_bg.png` `row_alt.png` | 1×1 | 分隔线、表头底色、隔行底色，拉伸使用 |

Java 侧**只做 blit**：`NineSlice` 把九宫格切成九块贴到任意矩形，不画边框、不画斜边。
唯一「像画图」的地方是用 1×1 贴图拉伸填充——那也是一次 blit。

这样做的好处：渲染代码简单、细节（内凹阴影、斜边）交给生成脚本、换主题只改调色板重新生成，
不用在 Java 里复刻一遍美术。

**色值必须两边一致**：`GuiTheme.AE2` 里的常量 ↔ `tools/gui/gen_textures.py` 顶部的调色板。
改色只改一边会造成贴图和文字脱节，而脱节在截图里看不出来。

## 6. P0 顺手清掉的东西

改成指令打开界面之后，这一整条链退场了：

| 删掉 | 原因 |
|---|---|
| `TerminalItem` + 物品注册 + 创造模式标签 | 没有物品了 |
| `ModAttachments`（玩家附件） | 只服务「装备奇点」 |
| `SingularityInteractionHandler` / `SingularityUnequipHandler` | 同上 |
| `UnequipSingularityC2S` / `StorageSnapshotS2C` | 随上面一起没了 |
| `Ae2StorageView` / `ClientPacketHandler` / `ItemGrid` | 被新链路取代 |
| 终端模型与贴图 | 物品没了 |

净效果：「打不开界面」从三条可能（没物品、没奇点、网络不对）降到一条（没执行命令）。
