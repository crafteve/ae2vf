## 1. 背景与动机

### 1.1 现状基线（2026-11-11 实测）

| 项 | 数值 |
|---|---|
| IO 链路相关文件 | 74 个 |
| 总行数 | 10695 行（io 包 2050、node 包 3992） |
| 「不搬 / 拒绝」出口 | 70 处（9 个 return 0L、37 个 continue、24 个 return false） |
| 每 tick 全表遍历 | 3 趟 |

### 1.2 四个症结

1. 一次「这台机器为什么不搬」的答案要靠 4 个类接力拼出：NodeIoRunner → MachineIoRunner → RuleResolver → IoTransfer，多数中间环节不写原因。
2. 70 个跳过出口里只有少数进入界面可见原因；变体额度耗尽、单机异常都是静默的。
3. 主动侧 4 个类共享隐式的「忙」语义，各自维护节奏（5 tick / 200 tick / 退避 / 每 tick flush）。
4. MachineIoRunner.runBlock 一个方法内同时处理：资源类型 × 方向 × 精确/模糊 × 面来源，四个维度的组合。

### 1.3 重复的事实与重复的派生（重构要消灭的）

- 方块事实有两份表示：Observation 与 BlockObservation（每 tick 投影重建）。
- 机器/节点结论有三条独立推算链：node/NodeHealthResolver、NodeStatusResolver、NodeIoRunner 自判。
- 变化有四条通知通道：dirty 集合、Transition 队列、面表 generation、能力监听器。

## 2. 目标

### 2.1 一句话

> 把 IO 重构成**一条带时钟的流水线**：观测层只管知道世界，配置层只管记录玩家意图，执行层每 tick 读这两份事实、排出这一 tick 该干的活、机械执行、记账，分析器把账压成结论供下一 tick 用；主动与被动共用同一个机器写入口。

### 2.2 六条必须满足

1. **每 tick 两段**：准备（观测 → 认仓库 → 机器状态）→ 执行（回收 → 队列 → 被动）。
2. **两个真相 + 一个视图**：机器状态、执行状态是真相（存）；节点状态是视图（读时拼，不存）。
3. **一张原因枚举**：所有「这一轮为什么不搬」收敛成它，界面直读；不再散落 return 0L / continue / return false。
4. **两个规划器，一个执行器**：被动规划器（tick）、主动规划器（AE2 同步 + tick）；执行器无跨轮记忆。
5. **主动与被动共用**：机器侧写入口（选面/模拟/写入/退款）、账本、分析器、历史结论。
6. **表单是唯一工作清单**：不在表单上的单元，执行层根本不认识它。

## 4. 约束与自由度

### 4.1 不能动

- 搬运事务不变式：**搬不进去的东西永远不离开来源**（feed / pull 的模拟-确认-退款语义）。
- AE2 接口实现与节点虚拟化方式（ICraftingProvider / PatternContainer / IGridNodeListener / 虚拟 IGridNode）。
- 规则归节点、作用于节点内每台机器；每侧上限 64 条。
- 节点可用性定义：节点内所有机器 PRESENT 才对外广告样板（产品行为）。
- 包依赖方向与命名后缀约定（Service / Runner / Store / Handler 等）。

### 4.2 可以动（已确认）

- **允许重建世界**：数据结构可自由改，不需要写旧档迁移。
- PROTOCOL_VERSION 可随意递增，客户端同步更新。
- 界面状态语义可重做。
- 规则级排期带来的观感变化（一条缺料不再拖累整机）接受。

## 5. 目标架构

### 5.1 分层

```
世界事件                     玩家事件
   │                            │
   ▼                            ▼
观测层（唯一探世界）        配置层（玩家意图）
   │ 世界事实                   │ 配置事实
   └───────────┬───────────────┘
               ▼
        IO 表单（唯一工作清单）
               │
               ▼
   机器状态（apply 唯一写入点）
               │
               ▼
   执行层：两个规划器 / 执行器 / 分析器 / 账本
               │
               ▼
   视图层（读时拼，不存）
```

### 5.2 三种状态

| 状态 | 来源 | 变化频率 | 性质 |
|---|---|---|---|
| 机器状态 | 世界事实 + 配置事实 | 低 | 真相，存 |
| 执行状态 | 执行层自己（睡眠、拒收、计数） | 高 | 真相，存，归执行层 |
| 节点状态 | 成员机器状态聚合 | 跟随成员 | 视图，不存，读时拼 |

判据：机器状态回答「它在不在」；执行状态回答「它这轮为什么没搬」；节点状态回答「这一组整体怎么样」。

### 5.3 两种驱动方式

- **执行层走 tick**：与 tick 强绑定，简单高效。
- **配置层走事件**：玩家操作天然是事件。
- 执行层不接收任何外部事件推送；它每 tick 自己抬头看表格。

### 5.4 三个角色

```
规划器（有跨轮记忆）  读：历史结论 + 表单；写：本 tick 执行清单
                       禁止：查方块、调第三方接口、搬东西
执行器（无跨轮记忆）  读：执行清单 + 配置；写：账本
分析器（只读）        读：账本；写：历史结论（值对象）
```

## 6. 每 tick 流程

```
每 tick（服务端主线程）
① 观测：一趟遍历 → 到期探测（预算内）→ 世界事实
② 认仓库（每 20 tick）
③ 生成 IO 表单：世界事实 + 配置，过滤掉不可用单元
④ 执行（串行，顺序即优先级）
     4a 回收：逐面找产物 → 模拟 → 抽 → 插网络
     4b 队列：主动待写入队列，每 tick 都试，按整数份投递
     4c 被动：按规则补料 / 抽产物
⑤ 分析器：吞账本行 → 更新历史结论
```

AE2 派单是旁路，不在这条时间线上：随时 pushPattern → 校验 → 整单入队 → return true；下一 tick 由 4b 消费。

## 7. 逐层需求

### 7.0 术语表（这些词是什么）

| 词 | 是什么 | 一句话 |
|---|---|---|
| **Form（表单）** | 数据结构 | 每 tick 由「世界事实 + 配置」生成的工作清单：这一 tick 哪些单元**有可能**干活。不在表单上的单元，执行层根本不认识 |
| **Unit（执行单元）** | 身份 | 表单上的一行 = (机器, 规则, 方向)。规划器按它排期、账本按它记录、聚合按它统计 |
| **Planner（规划器）** | 角色 | 每 tick 决定「表单上哪些单元这一轮跑、按什么顺序、用哪个面」。有跨轮记忆（游标；其余记忆来自 Digest）。两个：被动（tick）、主动（AE2 同步 + tick） |
| **Executor（执行器）** | 角色 | 拿一条执行指令（规则 + 方向 + 面 + 机器）去搬一次。**无跨轮记忆**，不判断该不该跑 |
| **Ledger（账本）** | 数据结构 | 环形有界的「变化序列」：每次执行结果一行，连续同结果合并。属于分析器，是短期结论 |
| **Digest（历史结论）** | 数据结构 | 分析器把账本压成的一组数（上次尝试时间、连续空转、面记忆、计数……），是值对象，规划器只读它 |
| **Analyzer（分析器）** | 角色 | 维护 Ledger 与 Digest 的角色，原 Diag 的继任者。只读账本、不参与判断 |

### 7.1 观测层

- 唯一允许探世界的地方；预算默认 64 次/tick（现有配置项）。
- 每 tick **一趟遍历**同时产出「探测清单」和「世界事实」；**配置本身就是登记表**，不另建引用索引。
- 事实只存一份；删除 BlockObservation 这类每 tick 投影层。
- 通知出口只有一个：本轮「哪些方块变了」。dirty / Transition / generation / 监听器 合并成这一条。
- 读路径不探世界。

### 7.2 配置层（本次不动）

- 维持现状：接住玩家操作 → 落盘 → 副作用散在 NodeActions 等处。
- 计划中不得顺手改配置层结构。

### 7.3 机器状态

**机器状态只回答「它在不在、能不能跑」，不回答「它这轮搬没搬」**——所以枚举里没有 SLEEPING。

- 枚举：**RUN / GONE / UNLOADED / UNSEEN**（UNSEEN 与 UNLOADED 必须分开：前者会自愈，后者不会）。
- 唯一写入点 apply(signal)：OBSERVED / CONFIG_CHANGED；穷尽 switch，外部不得直接改字段。
- 状态字段对外只读。
- **睡眠不属于机器状态**：它是执行层的节流判断，由分析器给的 `idleTicks` + `lastAttemptAt` 在规划器里算出"这轮跑不跑"；界面上显示「休息中（N tick 后再试）」时，数据来自执行状态，不从机器状态取。
### 7.4 IO 表单

- 每 tick 由「世界事实 + 配置」生成；不在表上的单元执行层不认识。
- 过滤条件：无配置（规则/机器不存在）、方块没了、区块未加载。
- 单元身份 = (机器, 规则, 方向)。规则归节点、执行归机器。

### 7.5 账本

- 一个环形有界列表（8 行/单元）；**Current 就是其中最新一行，不单独存**。
- 一行内容：结果原因 + 首次 tick + 末次 tick + 次数 + 累计数量 + 用的面。
- 是**变化序列**不是时间序列：连续同结果合并成一行。
- 账本属于分析器，是「短期结论」。
- 只给表单上的单元保留；离开表单即释放。

### 7.6 分析器与历史结论

- 分析器 = 账本 + 增量维护的长期聚合，产出一个值对象给规划器读。
- 规划器**读值对象，不读分析器**。
- 单元级聚合：lastAttemptAt / lastSuccessAt / lastFailureAt / idleTicks / rejectStreak / reasonCounts / faceHint。
- 节点级聚合：pendingCount（= isBusy）/ pendingOldestAt / entryAttempts / entryLastError / deliveredTotal。
- 命名后缀固定：At（绝对时间）/ Ticks（连续时长）/ Streak（连续次数）/ Counts（累计）/ Hint（经验值）。
- 聚合靠增量更新，不回放账本；账本是明细（会滚掉），聚合是摘要（不滚）。
- 重置：单元离开表单即丢弃；重新进入从零开始；key 变化即身份变化；面记忆在写入失败时就地清除。

### 7.7 规划器

- **两个规划器**：被动（tick 驱动）、主动（AE2 同步 + tick 驱动）。
- 只排「这一 tick」，不排未来；退避是每 tick 用「现在 − 上次尝试」重算。
- 排期颗粒度 = **规则级**。
- 决策内容：跑不跑（择时）、用哪个面（配置优先 → faceHint 兜底 → 探面）、顺序（游标，先输入后输出）、阻挡是否生效。
- 面记忆规则：显式配置的面优先；历史只在未配面时兜底；写入失败即清 faceHint。
- 主动规划器住节点层（它是样板供应器的一部分）。

### 7.8 执行器

- 无跨轮记忆：给一条执行单（规则 + 方向 + 面 + 机器）就搬一次。
- 唯一写路径：模拟 → 确认 → 写入 → 退款（沿用 IoTransfer 的不变式）。
- 不判断「机器在不在」——那是节点层与表单的事。
- 被动与主动共用同一套机器侧写入口；RuleResolver 与 ProviderFaceResolver 合并。

### 7.9 被动 IO

- 单元 = (机器, 规则, 方向)；每 tick 由规划器决定跑哪些。
- 输入规则先跑、输出规则后跑；同侧多规则按游标轮转，每条每轮只跑一次。
- 失败原因必须进入统一原因枚举并写账本。

### 7.10 主动 IO

- AE2 只跟节点层对话（ICraftingProvider 挂在哪，回调就在哪）。
- pushPattern：校验（忙 / 样板归属 / 阻挡 / 在线机器 / 能选面）→ **整单入队** → return true。
- 队列条目 = 一整单（含全部资源与数量，数量比即样板比例）、目标机器、绑定面（可空）。
- 投递按「能完整做几份」n 计算；n=0 一个都不写（防塞一半把机器卡死）。
- 队列**不退避**，每 tick 都试；主动尽量塞满，被动自然塞不进去，不做让位。
- 接单门禁归节点层：机器不在时拒绝接单；接单后在投递时消失 → 等一段后退回 ME 网络。
- 兜底：退回网络 → 网络也不收 → 静默丢弃（只记日志，**绝不生成掉落物实体**）。
- 回收：逐面（选面）+ 模拟（机器能给多少 / 网络能收多少）+ 取小的那份。
- 多个 CPU 任务冲突 → 由玩家开启阻挡模式。
- 不做任务台账；只暴露 pendingOldestAt / entryAttempts / entryLastError 供界面显示「有单卡住」。

### 7.11 视图层

- 从三份真相读时拼展示快照；不存、不参与判断。
- 节点卡片：在线/部分/离线（机器状态聚合）+ 机器数/规则数（配置）+ 正在搬/等料/堵塞/空闲（执行结论聚合）。
- 每台机器能显示「为什么不动」：读该单元的 idleTicks / rejectStreak / faceHint + 展开账本。
- 推送频率跟随现有快照机制。

### 7.12 命名与包归属（方向已定，细节留计划）

**命名后缀**：项目 AGENTS.md §2.1 有固定后缀表（Service / Runner / Store / Manager / Library / Ref / Anchor / Resolver / Adapter / Builder / Handler / Stats / Render / Messages / Refs）。下面这些新概念不在表里，最小新增方案是：

| 概念 | 建议类名 | 后缀 | 处理 |
|---|---|---|---|
| 表单 | IoForm | Form | **新增后缀**（需改 AGENTS.md） |
| 表单一行（执行单元） | IoFormEntry | Entry | 作为 record 名，不单独设后缀 |
| 被动规划器 | PassivePlanner | Planner | **新增后缀** |
| 主动规划器 | ActivePlanner | Planner | 新增（同上） |
| 执行器 | IoRunner | Runner | 复用现有后缀 |
| 账本 | IoLedger | Ledger | **新增后缀** |
| 历史结论 | LedgerDigest | Digest | 作为 record 名 |
| 分析器 | IoStats | Stats | 复用现有后缀 |

结论：需要新增 **Form / Planner / Ledger** 三个后缀；Entry、Digest 只作 record 名。AGENTS.md §5.6 规定修改它需单独审批，计划里要单列一条。

**机器侧写入口放哪**（D29）：

- 现状依赖：`io → node`（MachineIoRunner 直接引用 node.NodeIoGroup）。
- **方案 A（推荐）**：写入口放 `factory/io/`（暂名 MachinePortResolver），让 `node → io`。
  前提：必须先把 io 现在依赖的规则数据结构（NodeIoGroup / ResourceSpec）下沉到中立包（如 factory/machine 或新建规则包），否则形成 `io ↔ node` 环依赖。
- 方案 B：写入口留在 node，保留 `io → node`。
  代价：「执行层不认识节点」被打破（现状其实已破：io 认识 NodeIoGroup）。
- 推荐 A：它是唯一能让执行层对两条腿都保持中立的摆法；下沉数据结构作为计划中的独立一步。

### 7.13 主动队列的持久化（2026-11-12 修订）

- 队列**落档、跨重启恢复**。理由：`pushPattern` 返回 `true` 时材料已经从 ME 网络抽走，队列丢一单就是那批材料凭空消失、AE2 合成任务永久卡死。
- 旧格式不迁移：读档时丢弃旧的 `Pending` 格式（D26 允许重建世界）。
- 停机与删节点：队列退回 ME 网络；网络长时间不收才超时丢弃，只记日志，不生成掉落物实体（D21）。

## 8. 已定决策（计划不得冲突）

| # | 决策 |
|---|---|
| D1 | 每 tick 两段：准备（观测→认仓库→状态）→ 执行（回收→队列→被动） |
| D2 | 两个真相（机器状态、执行状态）+ 一个视图（节点状态）；视图不存 |
| D3 | 所有「不搬」收敛成一张原因枚举，界面直读 |
| D4 | 状态可存，但写入点只有一个（信号汇入、穷尽 switch） |
| D5 | 睡眠归执行层自维护，不进机器状态 |
| D6 | 账本 = 环形有界列表；Current = 最新一行；是变化序列 |
| D7 | 分析器产出历史结论值对象；规划器只读值对象 |
| D8 | 规划器只排这一 tick，不排未来 |
| D9 | 执行器无跨轮记忆 |
| D10 | 面记忆：配置优先、经验兜底；取消 RouteTable |
| D11 | 两个规划器（被动 tick / 主动 AE2 同步+tick）；执行器共用 |
| D12 | 排期颗粒度 = 规则级 |
| D13 | 表单是唯一工作清单；不在表单即不认识 |
| D14 | 观测层一趟遍历；配置即登记表 |
| D15 | 配置层走事件、执行层走 tick；不做仓库变化表 |
| D16 | 主动与被动共用机器侧写入口 |
| D17 | pushPattern 只做「校验 + 整单入队 + true」 |
| D18 | 队列按整数份投递；n=0 不写 |
| D19 | 队列不退避，每 tick 都试 |
| D20 | 执行层不判断机器在不在；接单门禁归节点层 |
| D21 | 兜底静默丢弃，不生成掉落物实体 |
| D22 | 回收 = 选面 + 模拟 |
| D23 | 不做主动任务台账，只做可观测 |
| D24 | 配置层本次不做 |
| D25 | 自动输出与「+」按钮本次不做（见第 11 节） |
| D26 | 允许重建世界、协议可递增 |
| D27 | 规模：1024 台设计，8192 台不崩 |
| D29 | 机器侧写入口放 io 包（node → io），前提是把规则数据结构下沉到中立包 |

## 9. 性能与规模

- 设计目标：1024 台机器；不崩上限：8192 台。
- 不设每 tick 硬性时间指标；先保证「不做增量优化也不卡」。
- 每 tick 允许的遍历：观测层一趟（O 单元数）+ 规划一趟（O 表单数，每项 O(1) 早退）+ 执行（O 到期数）。
- 账本内存量级：8 行/单元 × 1000 台 × 16 规则 ≈ 12.8 万行 ≈ 几 MB，可接受。

---

## 10. 验收标准

1. **行为等价**：原有被动搬运、主动合成、回收、余量行为不变（唯一必然变化：派单改为先入队、下一 tick 投递）。
2. **可观测**：任意一台机器「为什么不动」能在界面上一眼看出来（状态 + 原因 + 上次成功时间）。
3. **规则级排期生效**：同机一条规则缺料时，其它规则照常搬（现在会整机睡 10 秒）。
4. **规模**：1024 台机器下 tick 无明显抖动；8192 台不崩。
5. **代码指标（量级目标，非硬指标）**：文件 74 → 约 45；行数 10695 → 约 6000；「不搬」出口 70 → 约 12。
6. **无重复真相**：方块事实只有一份、机器/节点结论只有一条派生链。

## 11. 遗留需求（以后单独排期）

### 11.1 无白名单自动输出

- 归属：被动 IO 配置，是 IO 规则列表里的一条**通配输出规则**（无 key）。
- 参数：抽取模式（DIRECT 直接抽 / AUTO 只抽输出面 / SAFE 按判据过滤）+ 限定面。
- UI：节点卡片加「+」按钮，点击自动新增这条规则。
- 落地代价：ResourceSpec 允许无 key（或新增 rule kind）、存档/协议/界面渲染都要认。
- 判据（若走 SAFE）：产物优先 → 显式清单 → 排除集（主动用样板输入并集、被动用输入规则 key 并集）→ 模式决定。

### 11.2 配置层独立成层

- 目标：玩家事件一条通道、存档一个出口、服务端重校验一处。
- 代价：20+ 调用点要改，diff 大；边界易退化。

### 11.3 其他候选

- 滑窗统计（最近 N tick 成功率）。
- 主动单的任务身份与卡住报警。

## 12. 留给计划阶段决定的技术细节

以下**不要在需求阶段拍死**，写计划时再定：

- 包结构与类名（新类放哪个包、命名后缀选哪个）。
- 退避曲线的具体数值（空转多少 → 推迟多少 → 翻倍 → 封顶）。
- 原因枚举的完整取值列表（大致方向：RUN / SLEEPING / GONE / UNLOADED / UNSEEN / NO_FACE / BUDGET_OUT / NO_MATERIAL / FULL / REJECTED / ERROR）。
- IO 表单的数据结构（内联事实还是存引用；复用还是每 tick 新建）。
- 账本行的精确字段与合并边界（数量不同算不算同一串）。
- 视图快照的推送频率与增量策略。
- 迁移分几步、每步的验收点与回滚方式。
