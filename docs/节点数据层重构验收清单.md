# 节点数据层重构验收清单

> 状态：待用户执行
> 对应计划：`docs/节点数据层重构最终计划.md` §7
> 说明：本轮重构的测试全部由用户执行；本清单是逐条可勾选的验收步骤。旧存档不迁移，测试前请重建测试世界。

## 0. 环境

- 客户端与服务端协议必须都是 29；版本不一致会被拒绝连接。
- 建议先备份测试世界；旧世界加载为空是预期行为。
- 命令前缀统一用 `/idf`。

## 1. 数据与健康

1. 新建工厂，普通右键一台机器 → 节点终端显示 1 节点 / 1 机器 / 1 方块。
2. 保存退出重进 → 节点、机器、规则、样板还在；连续创建 / 删除工厂后新建工厂 id 不重复。
3. 用绑定杖 STACK 接 8 台熔炉 → 节点机器数 8、方块数 8；v3 卡片数量标识为 ×8。
4. 拆掉 3 台 → 节点显示缺机，剩余 5 台继续 IO；全部拆掉 → 离线。
5. 一台多方块机器拆任意部件 → 整台机器离线；同节点其他机器不受影响。
6. 节点内机器跨维度 → 允许；某维度区块未加载 → 对应机器离线，其它机器继续。
7. 部分机器掉线后原地换不同方块 → 不认，仍离线；换回同 id → 恢复。
8. 所有机器掉线且类型方块统一换成另一种机器 → 节点自动迁移类型，规则 / 样板 / 名字 / 机器 id 保留。
9. 未探测过的机器 / 节点 → 离线、`probed=false`，tooltip 显示「未探测」。
10. 调低观测预算与 `staleHealthTicks` → 超时后机器离线，tooltip 显示「健康过期」；调回后恢复。
11. 从未探测过的方块 → `probed=false` 且 `stale=false`，不能误报健康过期。

## 2. IO

1. 节点规则在 8 台熔炉上共用；v3 卡片下编辑一次，全部生效。
2. 节点缺机时只跑在线机器。
3. 物品无向、流体 / FE 按面；路由按方块隔离。
4. `NO_SPACE`（满）与 `REJECTED`（面不对）不混；`/idf diag why <机器>` 能看到节点 + 成员原因。
5. 连续多轮 IO 不会总是只喂第一台机器。

## 3. provider / 倍率

1. 一个节点一个 PatternContainer；样板终端按节点显示。
2. 8 台熔炉按派单模式轮询；一次货只进一台机器。
3. 目标机器收不下 → 余量进队列；只回原机器；原机器没了退 ME 网络。
4. 固定 ×2：AE 要 2× 输入、给 2× 输出；没有复制。
5. 智能倍率：一台机器能装 16 份 → ×16；8 台机器时 AE 发 8 次 ×16，节点依次塞入。
6. 探测失败 → ×1，tooltip 标「无法估算」；探测只读，不改变机器库存。
7. 阻挡按目标机器检查；被挡换下一台；全挡才失败。
8. 多方块：类型方块和 I/O 部件都能被 provider / 回收扫到。
9. 倍率溢出 / 超过硬上限的样板被跳过并记日志，不产生负数。

## 4. 绑定

1. STACK：蹲下滚轮切堆叠 → 蹲下右键第一台 → 右键 7 台 → 蹲下右键空气提交；节点出现 8 台。
2. MULTIBLOCK：切多方块 → 蹲下右键主方块 → 右键若干部件 → 蹲下右键空气完成。
3. STACKED_MULTIBLOCK：重复「蹲下右键开机器 → 右键部件 → 蹲下右键空气结束」，最后再蹲下右键空气提交；动作栏提示清楚。
4. 编辑已有节点：节点终端 `+`（主手绑定杖）或世界蹲下右键已有成员 → 追加机器 → 提交。
5. 草稿非空切模式 → 拒绝；蹲下 + 左键空气 → 取消。
6. 客户端简单核验：重复块、主手不是杖 → 动作栏提示。
7. 服务端校验：超上限、方块已属于别的节点、类型不符 → 整份拒绝；不留下节点 / 机器 / 占用残留。
8. 不校验距离：可在很远的两台同 id 机器之间完成同一节点绑定。
9. 不跨登录：退出重进、换维度、换手、把杖放进容器时草稿清空，不报错。
10. 事务回滚：草稿里混入一个已属于别的节点的方块 → 整份拒绝，`LinkRegistry` 无新占用，节点库无半成品。

## 5. v3 IO 终端

1. 堆叠节点一张大卡片；数量标识 = 机器数。
2. 节点卡片下规则 = 节点规则；增删改后所有成员生效。
3. 多方块节点占位：主方块图标 + 方块数 tooltip + 节点规则。
4. 节点卡片删除：第一次点击进入待确认，3 秒内再点一次删除整个节点；有规则 / 样板会一起删除。
5. LIST / TILE 两种视图、搜索、滚动、JEI 拖拽、tooltip、定位都正常。
6. v1 `FactoryScreen` 仍能打开，不崩；交互未改。

## 6. 指令 / 诊断 / config / 协议

1. `/idf machine` 仍按机器定位，但规则作用于节点；多机器节点回执写明影响范围。
2. `/idf node`（无参）列节点；`/idf node <id> info` 输出健康 / 机器 / 方块 / 规则 / 倍率 / 派单 / 阻挡。
3. `/idf node <id> rename|blocking|multiplier|dispatch` 与 `member add|remove` 可用；Tab 补全正确；回执 60 字内。
4. `diag why / watch / observe` 输出节点 + 成员；缺机 / 健康过期可见；节点事件带 nodeId。
5. config 默认 -1；改小只阻止新增，不删已有；`0` 被配置校验拒绝；中英注释可读。
6. 超过硬上限的值被 `min(config, 硬上限)` 夹住；超大恶意包被 `HARD_WIRE_ENTRIES` 拒绝，不 OOM。
7. 协议版本 29；客户端 / 服务端版本不一致时连接被拒。

## 7. 事务、对账与定位

1. 连续加 / 删同一节点的机器：每次结构变化最多重建一次；规则 / 名字 / 阻挡等非结构变化不重建；重建前后余量不丢。
2. 重启后同一节点仍用同一虚拟位置；人为制造位置碰撞时按固定盐重试，仍冲突则不建节点并报一次 ERROR。
3. 绑定提交失败后重试同一草稿能成功；失败不产生 `LinkRegistry` 占用，也不改旧节点。
4. 工厂删除 / 节点删除后 `LinkRegistry` 无残留占用；节点库无孤儿机器。
5. `NextSeq` 在保存 / 重载 / 删工厂后不回退，工厂 id 稳定。

## 8. 已知缺口（测试时留意）

- 世界蹲下右键编辑已有节点依赖最近一次机器表里的「方块 → 节点」映射；刚登录、还没打开过终端时可能匹配不到，此时用节点终端 `+` 进入编辑。
- 智能倍率的容量上限只按 64 硬顶，`maxMultiplier` 配置暂未参与智能探测。
- 多方块 / 堆叠的完整玩法验收依赖本清单第 1、3、4 节，建议按顺序执行。
