# 01-主动合成与虚拟样板供应器

> 状态：讨论中
> 最后更新：2026-10-31
> 标记：【用户已确认】/【用户想法·待确认】/【Agent 建议·未确认】/【用户已推翻】；技术判断归入 Agent 建议。
> 目标：AE2 CPU 把 Idle Factory 当成纯逻辑虚拟样板供应器；不新增方块 / IGridNode；产物回 ME。

## 【用户已确认】

- 纯逻辑 provider：用 `ICraftingService.addGlobalCraftingProvider`；per-grid；不注册方块 / IGridNode。
- CPU 能规划、能派单；接单入口拿 `KeyCounter[]`；产物回 ME，任务推进。
- 样板来源用 AE2 处理样板；填入后转虚拟数据存储，不保留实际物品槽。
- 机器删除时，样板还原成 AE2 处理样板物品吐出来。
- 机器失联时不向 CPU 广告，恢复后重新广告；显式删除才吐样板。
- ME 仓库 + CPU 是主动合成前提。
- `FactoryLive` 可以持活对象；数据层和 UI 都要改。
- Factory 对象绑定 ME 网络；机器绑定杖把机器绑到该工厂（后定，详见 03/04）。

## 【用户想法·待确认】

- 机器只接受处理样板。
- 样板挂在 Machine 下，`MachinePatterns` 与 IO 规则并列。
- 机器卡片的样板槽可无限扩展。
- 主动合成采用虚拟生产（不实际用机器加工）——最初方向，产品讨论后重新打开。

## 【Agent 建议·未确认】

- `PatternEntry` 存 `EncodedProcessingPattern` 的 NBT；`getDefinition()` 时合成 AE2 处理样板，不存 `ItemStack`。
- provider 聚合“有样板的机器 + PRESENT”，不再按 Line 聚合。
- `pushPattern` 只入队；产物下一 tick 起回传；队列满返回 false。
- 机器是唯一配置对象，Line 不再是数据对象。

## 【用户已推翻】

- 主动 / 被动产线作为数据对象、一个主动线、popup 新建主动线、同机器跨两条线：后被“只有 Machine 对象，Line 不需要”取代。

## 【Agent 建议·未确认】（技术判断）

- `ProviderState` 注册时快照 patterns / priority；改样板必须 refresh。
- push 前输入已扣到 CPU 库存；返回 true 即消费，false 自动回滚。
- `waitingFor` 在 push 返回后登记；不能在 push 内同步回产物。
- 产物必须走 ME 网络库存（`CraftingServiceStorage` 会先 `insertIntoCpus`）；多输出每个都要还。
- CPU 任务持久化只存 `getDefinition()`；读档用 `PatternDetailsHelper.decodePattern`；虚拟数据必须能还原成 AE2 可解码的定义物品。
