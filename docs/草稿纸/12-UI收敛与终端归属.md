# 12-UI 收敛与终端归属

> 状态：讨论中
> 最后更新：2026-11-03
> 目标：判断工厂配置是否该收敛成一个终端界面，以及第一版 / 第二版 UI 各自的得失。
> 结论见文末「[设计定稿](#设计定稿2026-11-03)」。

## 【用户已确认】

- （2026-11-02）**定位收敛为 AE2 附属**：只加虚拟 IO bus 与虚拟 provider。「一个 UI 解决所有问题、把 MC 玩成增量放置游戏」的初始目标不现实——MC 有种田、杀怪、多方块、采集、魔法，不是一个 UI 能接管的。
- （2026-11-02）**工厂监视界面按「加法」处理，不当及格线**：核心附属先做扎实，产量统计一类是可叠加项，不是模组成立的前提。

## 【用户想法·待确认】

- （2026-11-02）模组本质只加两件事：主动样板对接 AE（虚拟节点完成）、被动 IO 维持机器内水平（绑定在 Service 上的逻辑）。其余三块——仓库浏览、样板编写、样板管理——AE 都有替代品，所以可能只需要一个被动 IO 管理终端。
- （2026-11-02）第一版 UI：左侧被动 IO 配置 + 机器卡片语言（渲染 IO 状态与速率），右侧仓库与机器库，可从仓库拖拽物品配置左侧。
- （2026-11-02）第二版 UI：继承 AE 终端与美术、直接用 AE 贴图；左侧被动 IO 与主动样板配置，右侧合成终端与样板编码终端。受 AE 终端 195 宽度限制，槽位语言取代卡片语言，速率与状态渲染被删减。与 AE 匹配更紧密、可直接继承 AE 的合成 / 样板终端与搜索、物品渲染，但美术明显不如第一版。

- （2026-11-02）**不再要一个大 UI，要拆成 4 个小 UI**：机器库、机器 IO 配置、机器 IO 监视、样板配置（阻挡 / 智能阻挡等，定位为 AE 样板管理终端的升级版，参考 EAE 在 AE 基础上升级功能而非另起炉灶的做法）。
- （2026-11-02）数据侧不是瓶颈，瓶颈在 UI 侧：怎么把数据展现出来，以及怎么把玩家的配置翻译给数据侧。后者（输入侧）比前者更值得处理。
- （2026-11-02）**四个 UI 是平级关系，不是「机器库为根」**：机器库是工厂所有机器的管理、IO 配置是工厂所有机器的 IO 配置、IO 监视与样板管理同理。理由是 UX 的「操作越少越好」——玩家想配 IO 就直接打开 IO 配置，不应该先过一道机器库。
- （2026-11-02）**EAE 的升级版样板终端有终端形态**：它虽然绑定 `IGrid`，但我们可以走自己的链路拿到 `IGrid`，所以不依赖方块不是问题。
- （2026-11-02）**4 个 UI 模仿 AE 多个终端的风格，暂时不做同一 UI 内的切换**。
- （2026-11-02）两版 UI 在配置体验上有同一个病：旧 UI 要展开机器行才能改细节，新 UI 要点开槽位才能改细节——细节永远在「上一层」。
- （2026-11-02）**FE 不走 JEI 拖拽输入**：JEI 里有 `idlefactory:fe` 配料、能收藏后拖，但拖拽输入 FE 很别扭，而 FE 输入又是最常见的配置。改成一个开关，默认打开——绑定机器就自动传入 FE。
- （2026-11-02）**二级目录不是问题**：面、精确/模糊都是不常用的配置行为，完全可以收进二级界面。关键在一级目录的美术风格与交互设计。
- （2026-11-02）旧版 UI 更好，原因大约各占一半：一半是「长得有层次」（边框、阴影、状态条），一半是一级目录的信息密度。
- （2026-11-02）旧版难受在「必须展开才能方便配置」，而展开本身占一跳；之所以必须展开，是因为它要在同一个列表里配置机器库的所有机器——这与「机器库为根、点进 IO 配置」是同构的。
- （2026-11-02）**不做折叠，块内配置一律自动展开**：不要「默认折叠成 16px、点开才展开」那套，那等于把「必须展开」换个名字留着。用机器行把列表分成几大块，块内输入/输出槽位常驻展开，像代码块一样。

## 【Agent 建议·未确认】

- 三块里两块已经白拿、第三块技术上也是白拿：`MachineNode` 实现 `PatternContainer`，AE 原版样板访问终端通过 `getActiveMachines(PatternContainer.class)` 已经能看到每台机器（一台机器一个容器）。「样板管理交给 AE」不是设想，是现状。
- 左侧主动样板面板重画了 AE 样板访问终端，而且做成了「管理视图」；这个位置真正缺的是「上传视图」（写完样板 → 选目标容器 → 塞进去）。AE 里这步要在样板编码终端与样板访问终端两个方块间来回走，才是我们该补的缝。
- 「完全交回 AE 原版」是能白拿，不等于好用：机器多了以后样板访问终端里会堆出一长串「机器：xxx」容器。这是已知的 UX 债，先记下。
- 被动 IO 面板「美术差」不是手艺问题，是语言承载的信息维度问题：卡片语言天然挂 4–5 维（图标 / 名字 / 速率 / 状态 / 面），18×18 槽位只能挂 1–2 维，而一条 IO 规则恰好是 4 维（资源 / 方向 / 面 / 模式），余下的全挤进 tooltip，视觉上必然空、平、没信息。
- 不该退回卡片。正确做法是把「面 / 模式」收进点击后的配置框（`FactoryRuleConfigScreen` 已经是这个形态），槽位只留资源身份 + 一个状态点。
- 速率可以彻底不要：AE 自己从不给「这台机器在干嘛」做界面，机器状态归机器自己的 GUI。
- 失联状态点（MISSING / UNLOADED）必须留，但性质是**加法不是及格线**（2026-11-02 用户修正）：AE 的 IO bus 与 provider 都不会报告「对着的机器没了」；功能上我们也不会因此崩溃（`MachineRunner` 会跳过），缺的是可理解性而非可用性。它属于最便宜的一类加法——观测层已有数据，只差一个渲染点。
- 第二版的结构性错误不在美术，在于把同一台机器拆进「被动 IO」与「主动样板」两个视图：同一对象的两个属性分居，玩家判断「这台机器为什么不动」要来回切换。
- 真正的形态不是「一个独立的工厂工作台」，而是 AE 终端窗口内的多个可切换内容视图（不是并排）；第一版自建的仓库缓存、搜索、拖拽全部由 AE 提供。
- （2026-11-02，被用户修正后）**4 个视图平级，但必须共享「上下文」**：切视图时保留搜索词、筛选条件、选中机器与滚动位置。否则「配完 IO 切到监视看效果」会变成重新找一遍机器。
- （2026-11-02）**每个视图都是「机器行 + 本维度内容」的完整全表**，所以规模问题落在行高上。
  - **2026-11-02 用户否定**：不做折叠。折叠等于把「必须展开」换个名字留着，块内一律常驻展开。
- （2026-11-02）「操作更少」还能再省一步：视图之间做深链接——在世界里对机器用绑定杖直接进这台机器的 IO 配置，在样板视图点机器名直接跳到 IO 配置。
- （2026-11-02）**「4 个独立 UI」的一个附带好处**：不并排就不必锁 195 宽，IO 配置视图可以自己定宽。
  - **2026-11-02 用户否定其中一半**：面 / 模式不需要做成常驻控件，它们是低频配置，收进二级目录就行。
- （2026-11-02）独立 UI 的代价是跨屏 carry 会丢（`setScreen` 关容器，物品退回背包）。补偿手段是 JEI 拖拽——而且 JEI 比仓库更符合作意图：玩家配输入规则时想的是「这台机器的配方吃什么」，不是「仓库里现在有什么」。
- （2026-11-02）FE 自动供能可以做得更精确：绑定机器时探一次能量能力，有才自动挂输入规则，而不是无条件默认——避免给不需要能量的机器白挂一条规则；输出方向不默认（发电机产物另配）。
- （2026-11-02）**我给的「悬停浮出 / 常驻小字 / 就地弹层 / 打开新 Screen」四种方案是同一类**（用户指出）：本质都是在槽位这个小格子上打补丁。真正的分岔是「用槽位还是用卡片承载一条规则」——第一版的卡片是槽位 + 名称 + 速率 + 面按钮 + 匹配按钮，26px 高，一条规则的所有维度都在同一行内联；第二版把它们拆进了二级界面。
- （2026-11-02）**层次感必须自绘**：AE2 的贴图是为槽位设计的平面素材，卡片/块头需要的边框、内凹斜边、投影只能继续由 `tools/gui/gen_textures.py` 生成，配色与 AE 对齐。想「长得有层次」和想「直用 AE 贴图」不能同时全要——只能选「自绘但配色像 AE」。
- （2026-11-02）**第二版的「机器行 + 输入行 + 输出行」全展开块结构其实是正确的**（用户 2026-11-02 指出）：用机器行把列表分成几大块，块内配置常驻展开，像代码块一样——这正好消掉了「必须点击展开」这一跳。问题只在视觉：比较丑。
- （2026-11-02）**「丑」可以拆成层级倒置**：现在块内的 2px 槽位网格线视觉重量大，块头的机器名只是普通文字、视觉重量小，眼睛看到的是一整片网格，机器名像漂浮在上面的标签。应该是块头重、块体轻，现在是反的。配套修法：块头做成深色标题条（函数签名）、块体加浅色底与左侧缩进线、输入/输出用行首标签或颜色区分、块间留出空白。
- （2026-11-02，草图验证后修正）**深色块头不推荐**：`#3d3d4d` 跳出了 AE2 的色阶（面板 `#c6c6c6` → 标题行 `#b8b8b8` → 槽位 `#8b8b8b`），会重新变成「自造配色、跟 AE 格格不入」。推荐做法是**在 AE 已有色阶内做层次**：块头 `#a9a9b9` + 1px 下边框、块体 `#d8d8d8`。
- （2026-11-02，草图验证后新增）**分组靠贯穿竖线，状态也挂在竖线上**：每个块左侧一条 3px 竖线贯穿块头与块体，颜色即状态（绿 / 灰 / 红）。它同时解决三件事——块的边界、状态表达、失联定位（整条线变红比一个 3×3 的点显眼得多），且不占额外空间。
- （2026-11-02，草图验证后新增）**IN / OUT 做「语法高亮」**：标签与块头里的计数用蓝 / 橙两色，玩家扫一眼能判断这台机器以输入为主还是以输出为主。
- （2026-11-02，草图验证后新增）**悬停 = 行高亮**：整块换一档底色，像代码编辑器的当前行；不改布局、不推挤。

## 【用户已推翻】

- （2026-11-02）「一个 UI 解决所有问题、把 MC 玩成增量放置游戏」的初始目标：范围不可控，已放弃。

## 待定 / 分歧

- 【定位】模组叫 Idle Factory（放置工厂，核心数值是速率与产能），但 [10-终端化物理层](10-终端化物理层与主动被动搬运.md) 钉的定位是「补 AE 的物理层」（核心是接线正确）。两版 UI 的摇摆可能不是设计失误，是定位摇摆的症状：第一版是放置工厂的 UI，第二版是 AE 物理层的 UI。不选一个，第三版还会继续摇摆。
- 【布局】并排 414 宽（配置时能同时看仓库，但 GUI scale 3 下 1280 屏溢出，且同屏出现两个搜索框：左侧搜机器、右侧搜物品）vs AE 原生标签页 195 宽（一个搜索框，但配置时看不到仓库）。
- 【主动样板面板】改成上传视图 / 完全删掉 / 维持现状的管理视图。
- 【名称】「工厂」要不要退场。若退，UI 从「工厂标签页」变成「网络标签页」，机器表直接挂 network，少一层归属概念。
- 【观测】一个 3×3 的灯色点该放在哪：机器标题行，还是独立一列。

## 设计定稿（2026-11-03）

> 状态：讨论中，未实现。适用 IO 配置 UI，其余三个 UI 尚未讨论。
> 结论来源：2026-11-02 至 11-03 的多轮草图（`.tmp/ui-draft*.html`），已排除的方案列在末尾。

### 整体结构

- 4 个平级 UI：机器库 / IO 配置 / IO 监视 / 样板配置。模仿 AE 多终端风格，各自独立打开，**不做同一 UI 内切换**。
- 每个 UI 都是「全工厂 × 一个维度」的完整表，不是某台机器的详情页。切视图时保留搜索词、筛选条件与滚动位置。

### IO 配置 UI

**状态组收纳**
- 组顺序按「需要处理的程度」排，不按数量：**失联 → 未配置 → 运行中**。
- 默认展开、可折叠；失联组折叠后组头仍显示红色数量，避免被折叠功能藏起来。

**机器大卡片**
- 机器行（子卡片）：图标 + 名字 + 徽标位 + 状态点。
- 徽标位固定两个 16×13 空位：**堆叠数量（×8）**、**多方块标记（▣）**。功能未实现时显示虚线框，实现后直接填入，机器行高度不变。
- 磁贴区：规则磁贴 2 列**混排**，不按输入 / 输出分区。

**规则磁贴（24px 高）**
- 左边缘 3px 色条标识方向：**蓝 = 输入，橙 = 输出**。
- 上行：资源图标 + 名字（名字是磁贴里唯一的文字字段）。
- 下行：面 + 模式（9px 小方块）+ 速率（右对齐）。
- 混排的理由：MC 常见 9 进 1 出，左右分栏会严重不平衡；上下分区同样失衡。

**添加规则**
- 「+」放在**底部固定操作条**，不占磁贴格。9 进 1 出的长列表滚到底也始终可见。
- 操作条右侧预留**配置范围切换**（统一 / 单台），暂为虚线框，宽度待堆叠语义确定。

### 视觉语言（三条规矩）

1. **只用 AE2 已有色阶**：面板 `#c6c6c6` → 机器行 `#a9a9b9` → 磁贴 `#c2c2ce` → 磁贴区底 `#d8d8d8`。不引入深色块头一类自造配色——那是「搬 AE 搬得不彻底」的来源。
2. **状态挂在贯穿竖线上**：每张大卡片左侧 3px 竖线贯穿机器行与磁贴区，绿 / 灰 / 红即状态。它同时承担分组边界与状态表达，比小圆点显眼、且不占额外空间。
3. **IN / OUT 做语法高亮**：蓝 / 橙两色贯穿标签、计数与磁贴色条，扫一眼能判断这台机器以输入为主还是以输出为主。

### 已排除（附理由）

| 方案 | 排除理由 |
|---|---|
| 矩阵（行 = 机器，列 = 资源） | MC 的矩阵太稀疏；列数受资源种类限制 |
| 节点流（左进右出） | 太宽；MC GUI 适合长不适合宽 |
| 固定 9 格网格 | 信息密度低，每格只装得下一个图标 |
| 左右 / 上下分栏 | 9 进 1 出无法平衡 |
| 书页状 master-detail | 建立「目录-内容」从属关系，与 4 UI 平级冲突 |
| 折叠行（默认 16px，点开才展开） | 等于把「必须展开」换个名字留着 |
| 列表行（一条规则一整行） | 信息最全，但磁贴感消失、一屏机器太少 |

### 待定

- **堆叠机器的配置语义**：统一 / 分别 / 混合（推荐混合：默认统一，单台可脱离）。
- **多方块机器**在 UI 上的表示方式：徽标够不够，是否需要结构图。
- **「未配置」的判定**：零规则算未配置，还是「有输入没输出」也算。
- **4 个 UI 的入口方式**：一个物品 + 4 个菜单 / 快捷键 / 其他。
- **样板配置 UI**的布局：尚未讨论。
- 磁贴尺寸是否继续调整（当前 24px，2 列）。

## 实现注记（2026-11-03）

> 第三版被动 IO 终端实现阶段，用户对上面「设计定稿」做的调整；后续以此为准。

- **不做分组**：失联 / 未配置 / 运行中三组取消，机器按机器库登记顺序平铺，避免状态变化导致卡片跳动。
- **不做卡片外框**：机器行 + 规则行 + 虚线新增行是平铺的块，块边界靠左侧 3px 状态竖线和机器行深底表达。
- **操作条改成 IO 列表末尾的虚线空行**：拖 JEI 资源到这里新建行；不再有「+ 添加规则」按钮与「统一配置」占位。
- **面 / 模式不再收进二级目录**：方向、面、匹配模式各一枚 11×11 chip 直接放在规则行内；方向默认输入，点方向 chip 直接换边。
- **密度**：20px 行 + 16×16 图标（衬 18×18 凹槽），不是定稿图的 16px 行 + 12px 图标。
- **面为任意时显示「任」**。
- **视图切换保留在左侧工具栏**，不做头部两枚直选按钮。
- 速率列 38px；FE 去掉「 FE」后缀，完整单位进 tooltip。
