# 10-终端化物理层与主动被动搬运

> 状态：讨论中
> 最后更新：2026-10-31
> 标记：【用户已确认】/【用户想法·待确认】/【Agent 建议·未确认】/【用户已推翻】；技术判断归入 Agent 建议。
> 目标：把产品定位钉在“把物理层搬进 AE 终端”，并划清虚拟 provider 与虚拟生产、主动与被动搬运的界线。

## 【用户已确认】

### 产品定位

- 目标：AE 能把科技包的配方层全部终端化（写样板 → 上传 → 下单 → CPU 执行）；卡住的是物理层——机器本体、样板供应器、线缆 / 面、产线 IO。我们要补的就是物理层。
- 虚拟 provider 替代的是“样板供应器的摆放与接线”，不是加工本身：材料真的进机器、机器真的加工、产物真的抽回 ME。跟“虚拟生产”（凭空算出产物）不是一回事。
- 这条界线是设计红线，后续任何方案都不能滑向虚拟生产。

### 资源类型范围

- **资源类型的覆盖范围 = AE2 原生 + 已安装的 AE 生态附属，模组自己不新增任何资源类型。**
- FE：以安装 Applied Flux 为前提，没装就没有 FE 功能。装了时 `FluxKey` 继承自 `AEKey`，FE 就是一个普通资源，走同一条 `ResourceSpec`。
- 化学品：以安装 Applied Mekanistics 为前提，没装就没有化学品支持，不自己写。
- 推论：`ResourceSpec.key` 就是 `AEKey`，不需要 `IoKey` 之类的包装；`ResourceKind` 枚举整个删除（含 CHEMICAL 占位）。
- 没装对应附属时不做降级表示、不造平行 key，模组只支持物品和流体。

### 收窄范围

- 不做 GUI 内放置 / 破坏机器：技术上问题太多，退一步。
- 玩家自己摆放机器方块；模组只负责虚拟 bus、虚拟 provider、绑定机器、机器生命周期、IO。

### 节点与存储的绑定关系

- `storage` 绑定 ME 时，视为已绑定 AE，允许使用虚拟节点；`storage` 绑定容器时，不允许使用虚拟节点。
- 被动 IO 始终不是虚拟节点；主动样板 provider 始终是虚拟节点。
- 推论：虚拟节点是「主动合成的身份」，不是 IO 的发动机。容器阶段只有被动 IO，接入 ME 后才解锁主动合成。
- 前期可用是产品承诺：装了 AE 模组但还没建 ME 网络时，箱子当仓库也能跑被动 IO。

## 【用户想法·待确认】

- 虚拟 provider 的搬运逻辑与被动产线搬运“有地方可以合并，但不全是”。
- 被动 = 配置输入输出，机器持续工作；主动 = 配置样板，必须下单机器才工作。

## 【Agent 建议·未确认】

### 主动与被动怎么分

- 合并的是“搬运动词”：从仓库抽、塞进机器面、从机器面抽、塞回仓库，这一层是同一套 `IoTransfer`。
- 不合并的是“调度”：被动是常驻循环 + 睡眠退避；主动是任务驱动（样板 + CPU 派单 + 完成判定 + 任务生命周期）。
- “机器始终工作 / 必须下单才工作”不是机器行为，是我们的进料策略：被动维持一个库存水位；主动只在有任务时进料、任务结束清空。

### 主动真正的难点

- 不是搬运，是“完成判定”：怎么知道这一批加工完了——输入槽空、输出槽出现产物、working 状态回落，信号强度不同。
- （2026-10-31 定）完成判定不需要我们写：CPU 自己把期望产物记进 `waitingFor`，产物插进网络时被 `CraftingServiceStorage` 截获、计数清零即完成。我们只负责把产物搬回网络。
- 边界：产物被别的抽取器 / 玩家拿走怎么办；机器停机 / 失联 / 换配方怎么办；任务超时怎么收尾。

### 砍掉 GUI 放置的连带影响

- 不再需要 `MachinePlacementService`、`PlaceMachinePayload`、放置距离 / 权限 / 区块校验这一整套；机器方块生命周期交回原版。
- 我们只做观测：方块在不在（PRESENT / UNLOADED / MISSING），失联不写档。
- 名字仍可叫“放置工厂”：放置体现在玩家摆好之后不再需要操作，而不是模组替玩家摆。

### 虚拟样板 provider 的创建

- 节点在机器绑定到工厂时创建，**不是等有样板才建**：样板访问终端靠 `IGrid.getActiveMachines(PatternContainer.class)` 发现设备，没有节点就看不到，AE2 附属的「自动上传样板」也就没有目标。
- 每台机器的节点 owner 实现 `PatternContainer`，样板终端因此能看到它、往里传样板。
- `ICraftingProvider` service 仍然只在有样板时才挂：它只影响 CPU 合成规划的遍历，跟「能不能被上传」无关。
- 样板全删不销毁节点；机器从工厂删除时才销毁；失联时保留节点，只是不广告样板。
- 改样板后必须 refresh provider，否则 CPU 看到的是旧快照。
- 虚拟节点不占频道（2026-10-31 定），所以「每台机器一个节点」没有频道成本；只保留极低的待机耗电。

## P3-1 虚拟样板供应器（2026-10-31 定案）

### 形态

- 【用户已确认】一个逻辑机器 = 一个虚拟节点 = 一个样板容器 = 一个 provider；节点不占频道，所有节点共用一个锚点（从 `MeAnchor` 的方块坐标拿 `IGridNode`）。
- 【用户已确认】节点在「机器绑到工厂且仓库是 ME」时创建；容器模式不建；容器 → ME 补建，ME → 容器全拆。失联保留节点，只是不广告样板。
- 【用户已确认】节点 owner 实现 `PatternContainer`，样板访问终端按机器看到一个容器；`ICraftingProvider` 常挂（AE2 的节点服务只能在 `create` 之前挂，做不到“有样板才挂”）。
- 【用户已确认】样板槽动态扩容：默认 9，放到「容量 - 1」时 +9，上限用常量护栏。
- 【用户已确认】样板槽只收处理样板；合成 / 锻造 / 切石样板不支持。

### 派单与回收

- 【用户已确认】推送与回收照 AE2LT 的思路，我们只多一个「自动选面」：先用该机器输入规则里同 key 的面，没有就六面自动探。
- 【用户已确认】阻挡是机器级开关 `BlockingMode{OFF, ON}`，默认 OFF，按 AE2 原版语义：机器里存在样板输入就整单拒绝；判据只看样板的输入 key，升级插件这类不在输入集合里的东西不算阻挡物。整机粒度（不是单面）。
- 【用户已确认】不阻挡模式不记任务台账：CPU 推到机器塞不下为止，产物由常驻回收搬回网络。
- 【用户已确认】回收白名单只放样板产物，不加容器物品（处理样板没有容器残留）。
- 【用户已确认】燃料 / 催化剂不写进样板；写了导致整单失败是正确行为，和 AE2 一致。
- 【用户已确认】删除机器时样板退回玩家背包，装不下就地掉落。
- 【用户已确认】指令：`/idf machine <id> blocking on|off`、`/idf machine <id> provider`（节点 / 样板 / 阻挡 / 余量诊断）。

### 实现约定

- 【Agent 建议·未确认】节点用 `GridHelper.createManagedNode` + `setInWorldNode(false)`，空闲耗电 0；不存节点 NBT，重启按机器记录重建。
- 【Agent 建议·未确认】推送按 AE2 语义：每个输入至少能收 1 才提交，塞不下的进 `sendList`，每 tick 重试，`sendList` 随机器记录持久化。
- 【Agent 建议·未确认】回收节奏 20 tick 起、空闲退避到 128，派单前先扫一次；产物先进网络库存，CPU 自己判定完成。
- 【Agent 建议·未确认】自动选面不缓存；样板扩容上限暂定 1024 槽；样板优先级固定 0。

## 待记的实施细节

- （2026-10-31）**storage 从容器切到 ME 时要补建虚拟节点**：容器阶段不建节点，切到 ME 后已有机器没有节点，样板终端看不到。做法是切换后打标记、分帧补建，不在切换当 tick 同步遍历，避免机器多时卡顿。
- （2026-10-31）**开发阶段不做存档兼容**：不写旧档迁移代码，数据结构变了直接弃档。等发布前再统一处理一次。这条适用于所有重构阶段。
- （2026-10-31）**删产线连带丢掉“堆叠组”批量操作**：原来左表一行代表一组同型号机器，滚轮改台数、整组配规则；改成一台一行后这些交互消失。这不是要恢复产线，P3 的终端视图要用「多选 + 批量配规则」把它补回来。
