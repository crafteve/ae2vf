# 09-当前设想汇总

> 状态：讨论中
> 最后更新：2026-10-31
> 目标：把当前产品/架构设想按“已确认 / 待确认 / Agent 建议”整理成一页。
> 定位已细化，见 10：补的是 AE 的“物理层”（机器、样板供应器、线缆 / 面、产线 IO）；不做 GUI 内放置 / 破坏机器。

## 【用户已确认】

### 产品

- AE2 附属模组，AE2 硬依赖，不做脱离 AE2 的独立版本。
- 无线管理机器的被动 IO 与主动样板合成；没有方块、没有 BlockEntity，全局逻辑跑在服务端 tick。
- 机器是唯一对象；Line 不再是必须的数据对象。
- Factory 绑定 ME 网络，不按玩家；一个 ME 网络最多一个 Factory。
- 机器绑定杖把机器绑到该网络的 Factory。
- 需要 UI；复用 / 继承 AE2 的 `WirelessTerminalItem`，在 AE2 终端界面上改，不另写一套 UI。
- 用 AE2 原版无线访问点（WAP）作为 Factory 的绑定 / 创建入口：终端绑到 WAP，网络没有 Factory 就创建。
- ME 存储 + CPU 是前提。

### 机器与样板

- 主动合成以 AE2 处理样板为源，转成虚拟样板数据；机器删除时弹出样板。
- 机器失联时不广告样板，恢复后继续，行为对齐 AE2 样板供应器。
- 一机一节点。
- 虚拟化 AE2 的 bus / provider：机器是虚拟节点，Factory 不是节点。
- 样板访问终端按机器分容器，这是目标。
- `PatternProviderLogic` 是 BE 专用，不复用它；拆开实现样板槽、provider、推机器、返还、blocking、priority、`PatternContainer`。

### 机器定义

- 机器定义不能太严；一个机器对象可以代表 n 个方块实体（批量熔炉、多方块、自定义对象），以后再实现。
- 一个逻辑机器 = 一个 `MachineAgent` = 一个虚拟节点 = 一个样板容器 = 按 1 个频道计。

### 重写与虚拟节点接入

- 从头开一条新分支重写模组，不在现有基础上改；可以借鉴机制，但必须读懂后自己写，不照搬。
- 虚拟节点不设频道限制：不加 `REQUIRE_CHANNEL`，不占频道。
- 接入方式：沿用 `MeAnchor`（存储锚点）的方块坐标拿到 `IGridNode`，所有虚拟节点都连到这一个锚点节点上。
- 不选面、不做 hub、不重排连接表。
- 工厂容量暂不设限，以后再说。

## 【用户想法·待确认】

### 去 Factory 化

- 机器绑定杖绑定机器，创建虚拟节点；频道绑定杖把虚拟节点绑到 ME 网络。
- 绑定数据自己存一份；加载存档时读取配置，重新注册虚拟节点。
- 不需要 Factory 这个全局实例。

### 存储

- 删除容器后端，容器改为 ME 的外部存储，并入 ME 存储（ME-only）。

### 其他

- Factory 可以退成虚拟网关 / 经纪人，不一定是节点；这一条用户自己还不确定。
- AE2 没有安全终端了，WAP 取代它的位置（Agent 认为 WAP 只提供接入，不提供权限）。
- 只做处理样板；样板挂在 Machine 下；样板槽无限 / 可扩展；虚拟生产 vs 真实机器加工。
- AE2 自己的机器（分子组装机、驱动器、刻印机等）是否纳入管理。
- 权限 / 成员管理 UI。
- WAP 是唯一创建入口，还是保留 `/idf factory create`。
- 同 grid 多个 WAP 是共享一个 Factory，还是其他规则。

## 【用户已推翻】

- 每个 `IGrid` 创建时自动建一个 `FactorySession`；用户认为网络创建时建 Factory 运行时没有意义，改为绑定网络方块时创建。
- （2026-10-31）频道限制：虚拟节点不再按数量吃频道，也不再把虚拟连接排到物理连接前面。原「频道绑定杖 / 虚拟 dense hub / 32 个吃满 / 12 个剩 20」全部作废，改为不占频道、统一挂一个锚点节点。

## 【Agent 建议·未确认】

### 命名收敛

- `Factory`：存档数据。身份、canonical anchor、`FactoryAccess`、机器表、频道绑定。
- `FactorySession`：每个 `IGrid` 一个运行时实例，随网络创建；持有机器 agent、频道 hub、节点建/连/拆逻辑。
- `FactoryAccess`：存档 ACL，owner + members。
- `Machine`：存档数据。parts、IO 规则、样板、显示名。
- `MachineAgent`：每个逻辑机器的运行时 owner；持虚拟节点、两个 service、运行状态。
- `MachineIoService`：节点 service，`IGridTickable`，跑 IO。
- `MachinePatternService`：节点 service，`ICraftingProvider` + `PatternContainer`，管样板。
- `ChannelBinding`：存档数据，面/方向/顺序。
- `ChannelHub`：运行时虚拟 dense hub，连绑定面，机器节点挂它。
- `FactoryStore`：存档读写。
- 删掉 `MachineLibrary`、`NodeLifecycle`、`FactoryRegistry`、`ChannelHubAgent`、`FactoryAcl` 这些并列命名：机器表在 `Factory` 里，生命周期是 `FactorySession` 的方法，查找走 `FactoryGridService`，ACL 叫 `FactoryAccess`，hub 叫 `ChannelHub`。

### Factory 创建与锚点

- 不再每个 `IGrid` 自动建 `FactorySession`；网络先存在，Factory 是附属层，不绑就没有。
- 绑定杖右键 ME 方块面 → `GridHelper.getExposedNode` 拿节点 → `node.getGrid()` → 创建 / 打开 Factory；anchor 就是该方块位置。
- anchor 不要求 BlockEntity；cable / part / WAP / controller 都可以，WAP 只是可选的稳定锚点。
- `Factory` 数据存 `FactoryStore`（anchor + 配置）；`FactorySession` 只在已认领且 grid 可用时存在，detach / destroy 不删数据。
- 加载：读 `FactoryStore` → 按 anchor 找节点 / grid → 创建 session attach；anchor 未加载则休眠。
- `IGrid` 没有持久 id；没有 anchor 就无法在重启后说“这个档案属于哪个网络”。分布式 UUID 写进每个节点 NBT 理论可行，但复杂且容易在分裂/合并时冲突，不做。
- 一个 anchor 一个 `Factory`；同 grid 多入口共享一个 Factory。grid 分裂时 Factory 跟 anchor；合并时两个 Factory 冲突，保留一个、另一个休眠并提示。

### 去 Factory 化的最小结构

- AE2 模型是“设备自管 + grid 聚合 + service 汇总”：没有中央 Factory；设备自己存配置、自己 tick、自己注册服务。
- 我们只负责把虚拟节点接进 grid，并提供节点 service；连接、频道、能量、tick 调度、服务聚合交给 AE2。
- 运行时 Factory 可以去掉；全局 `NodeManager` 只负责从存档重建虚拟设备，相当于 AE2 从方块重建节点。
- 可选保留一个持久 `NetworkProfile`（anchor、ACL、频道绑定），但它只是配置记录，不是运行时管理器。
- `Machine` 记录自包含：parts、IO、样板、networkProfileId、节点 NBT。
- `MachineAgent` 每台机器一个，持有节点和两个 service；`ChannelHub` 每个频道绑定一个。
- 加载：`NodeManager` 读 `NetworkProfile` 和 `Machine` → 按 anchor 找 grid → 重建 `MachineAgent` / `ChannelHub`。
- UI 仍可叫 Factory，但它只是 `NetworkProfile` 的一个视图，不是运行时对象。

### 谁管什么

- `FactorySession` 管节点生命周期和拓扑：创建 / attach / detach / destroy `MachineAgent` 与 `ChannelHub`。
- `MachineAgent` 管自己的节点和 service 组装；只读 `Machine` 配置，不写存档。
- `MachineIoService` 管 IO 执行；`MachinePatternService` 管样板广告 / 派单 / 容器视图；两者分开。
- `Factory` 管持久配置和 ACL；不持有节点，不跑每 tick IO。
- 节点 NBT 归 `MachineAgent` / `ChannelHub` 保存，启动后恢复；`Factory` 只存 anchor 和配置。
- 子网上的机器可以绑到主网 Factory：虚拟节点活在 Factory 的 grid 上，机器方块在哪个子网只影响能力访问，不影响节点归属；子网自己的空 session 不受影响。

### 频道（2026-10-31 作废，改为不占频道）

- 虚拟节点不再 `REQUIRE_CHANNEL`：不占频道、不走 pathing 配额，也就没有连接表顺序问题。
- 代价：失去「按设备数收频道」的规模护栏；性能上限改由我们自己的遍历上限约束。
- 原「频道绑定杖 / 虚拟 dense hub / 重排连接表」三条方案全部作废，保留在此仅供回溯。
- 但虚拟节点仍然要耗电，网络没电时节点离线。

### 样板与 UI

- 样板数据 / 解码复用 AE2：`IPatternDetails`、`EncodedProcessingPattern`、`AEProcessingPattern`、`PatternDetailsHelper`。
- 样板管理自建：机器上的虚拟样板列表；`PatternContainer` 提供虚拟 `InternalInventory`，让样板访问终端看到每台机器一个容器。
- `PatternProviderLogic` 不复用；`PatternContainer` 是内部接口，版本锁死。
- 终端继承 `WirelessTerminalItem`，覆盖 `getMenuType()` / `getMenuHost()`；自定义 menu 继承 `MEStorageMenu`，screen 继承 `MEStorageScreen` / `AEBaseScreen`，加 Factory 标签页。
- WAP link 走 `GridLinkables` + `IGridLinkableHandler`，终端存 `AEComponents.WIRELESS_LINK_TARGET`。

### 权限与网络

- AE2 19.2.10 已没有安全终端 / 安全服务；WAP 不是权限系统。
- 需要自有 ACL：creator + members；可选接 FTB Teams 等团队模组，不做硬依赖。
- 服务端权威；客户端只发意图；快照按权限过滤、分页 / 增量，不整段发样板 NBT。

### 重写

- 新分支可以，但先写产品 / ADR，再按垂直切片写。
- 旧代码只做行为参考，保留行为清单（simulate 边界、组件身份、面探测、睡眠/退避、CPU 时序、NBT 兼容），不照搬。
- 先 spike：虚拟节点 + WAP / 面连接 + 频道 + `ICraftingProvider` + `PatternContainer` + 存读 + 样板访问终端。

## 最关键的未定项

- 频道绑定杖是走“反射 / AT 重排连接表”，还是退回“专用面”。
- Factory 作为无节点 gateway 的边界：它只管理 hub，还是也参与频道配额。
- 未认领的 grid 是否要自动生成持久 `Factory` 档案，还是只保留运行时 `FactorySession`。
- 重写先做哪条垂直切片：FactorySession / WAP 认领 / MachineAgent / 频道 hub / 样板终端。
- ME-only 存储与容器后端是否最终删除。
- AE2 自有机器是否纳入管理。
