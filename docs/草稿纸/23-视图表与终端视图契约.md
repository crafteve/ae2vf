# 23-视图表与终端视图契约

> 状态：讨论中
> 最后更新：2026-11-19
> 目标：定下读侧唯一的「视图表（ViewTable）」的数据结构、字段瘦身、全量 / 差量推送与终端视图契约。

## 已确认

【用户已确认】2026-11-18：视图表（`ViewTable`）是服务端每次推送时**临时组装**的只读数据表，不写档、不做业务缓存；俗称「信封」，**不叫「模型 / Model」**。唯一例外：`ViewPort` 在终端打开期间保留“上一次已发送的表”作为差量基线，最后一个会话关闭时丢弃。

【用户已确认】2026-11-18：采用单表方案，只有一条逻辑视图通道；新增终端只加客户端取数与绘制，服务端不改。通道由三个报文组成：请求、全量、差量，三者是同一通道的三种角色，不是三张表。

【用户已确认】2026-11-19：视图表是节点维度的界面事实（节点、聚合规则、机器身份与健康）；被动 IO 终端按节点分块展示（节点一行，规则聚合），节点终端取节点行。

【用户已确认】2026-11-19：发包越小越好，只发界面能用的字段；服务端负责组合与计算，客户端只取参数画界面，不做二次计算（颜色映射属于表现层，允许客户端做）。

【用户已确认】2026-11-19：增量包只计算与上一次已发送表的差异；首次 / 重开 / 版本对不上时发全量。

【用户已确认】2026-11-19：时间类计数一律砍掉：`sinceMoveTicks`、`blockedTicks`、`sinceInputMoveTicks`、`idleTicks` 不进视图表。

【用户已确认】2026-11-19：剩余瘦身清单全部砍掉：规则 `amount`、`beTypeId`、`groupBlockId`、`workState`、`inputFull`、机器级 `inputReason` / `outputReason`。

【用户已确认】2026-11-19：`pendingOldestAt` 保留原值，客户端格式化等待时长。

【用户已确认】2026-11-19：先做「节奏一」——增量只在终端打开期间生效；关闭后重开一律全量。

【用户已确认】2026-11-19：视图表**不传每台机器的运行状态**。服务端按节点规则聚合：速率取成员求和，原因取最严重的一个，只下发每条规则一行（速率 + 原因）。

【用户已确认】2026-11-19：简化结构——规则合成一个列表（`side` 区分方向，行类型 `ViewIoRule`，带聚合后的 `rate` / `reason`）、craft 四项内联到节点、去掉派生计数（`machineCount` / `ruleCount` / `nodeCount`）。

【用户已确认】2026-11-19：规则身份 = `(side, key)`，机器身份 = `machineId`；彻底取消 slot，`ViewTableBuilder` 无状态。

【用户已确认】2026-11-19：**删除 `NodeStatus` 记录与 `NodeStatusBuilder`**，把 `probed` / `stale` / `health` / `activity` 四个字段直接放进 `ViewNodeCore`（`ViewNode` 持有 `core`）；聚合逻辑内联到 `ViewTableBuilder` 构造节点行的那一步；`NodeStatusCodec` 一并删除。

【用户已确认】2026-11-19：`TotalState` 顶层枚举删除，改为 `ViewNode` 的**内嵌枚举 `ViewNode.Activity`**；`ViewNodeCore.activity` 用它，取值保留 8 个（RUNNING / INPUT_OK / IDLE / WAITING_MATERIAL / INPUT_BLOCKED / OFFLINE / UNCONFIGURED / UNKNOWN）。

【用户已确认】2026-11-19：类名定稿——`ViewTable`、`ViewHeader`、`ViewNodeCore`、`ViewNode`（内嵌 `Activity`）、`ViewIoRule`（内嵌 `Key`）、`ViewMachine`、`ViewTableBuilder`、`ViewTableDiff`、`ViewPort`；报文类名为 `ViewTableS2C` / `ViewTableDiffS2C` / `ViewTableRequestC2S`，去掉 `Factory` 前缀。

【用户已确认】2026-11-19：绑定杖继续使用自己的 links 通道（`FactoryLinksRequestC2S` / `FactoryLinksS2C`），不接 `ViewTable`。

【用户已确认】2026-11-19：列表 / 磁贴视图偏好与排序偏好继续独立，不并入 `ViewTable`（它们写物品组件，跟玩家走）。

【用户已确认】2026-11-19：改名——`ModNetwork` → `IdleFactoryNetwork`；`ResourceKeyCodec` → `AeKeyCodec`（与 `AeKeyAdapter` 对齐：Adapter 管语义，Codec 管网络字节）；`NoticeHandler` → `ObservationNoticeListener`（它监听观测变化，不是消息处理器）。

【用户已确认】2026-11-18：当前八阶段重构的执行与测试暂时收尾；视图表与终端视图契约另立一轮。

## 已确认（续）

【用户已确认】2026-11-19：全量与差量都**按字节预算分片**（按量，不按节点数）；在单包上限内尽量少分片，客户端收齐后拼装。

【用户已确认】2026-11-19：差量**按节点分组**，单节点差异用 `ViewNodeDiff`（节点字段、规则增删改、机器增删改）；规则增删只影响规则行，机器增删只影响机器行。

## 最终结构

```
ViewTable
├─ ViewHeader { hasFactory, storageOnline }        // revision 在报文里
└─ nodes: List<ViewNode>
     ViewNode {
       core: ViewNodeCore,
       rules: List<ViewIoRule>,
       machines: List<ViewMachine>
     }
     ViewNodeCore {
       nodeId, name?, typeBlockId, order,
       probed, stale, health, activity,      // activity 类型 = ViewNode.Activity
       patternCount, pendingCount, autoEnergyOnly, pendingOldestAt,
       available, blocking, multiplier, dispatch
     }
     ViewNode.Activity = RUNNING / INPUT_OK / IDLE / WAITING_MATERIAL /
                         INPUT_BLOCKED / OFFLINE / UNCONFIGURED / UNKNOWN

     ViewIoRule { side, key, face?, mode, order, rate, reason }
                            // side = 输入/输出；face = 访问面，空 = 任意
     ViewIoRule.Key { side, key }             // 删除身份

     ViewMachine { machineId, block, blockId?, health, probed, stale, order }

ViewTableDiff {
  baseRevision, revision,
  header?,                                   // 变了才带
  nodes: List<ViewNodeDiff>
}
ViewNodeDiff {
  nodeId, remove?,
  core?,                                     // 节点自身字段
  ruleUpserts[], ruleRemoves[],              // 删除用 ViewIoRule.Key
  machineUpserts[], machineRemoves[]         // 删除用 machineId
}
```

## 层类与功能（重构后）

### view

| 类 | 功能 |
|---|---|
| `ViewTable` | 整张视图表：表头 + 节点列表 |
| `ViewHeader` | `hasFactory`、`storageOnline` |
| `ViewNode` | 节点行：身份、排序、四个结论字段、计数、craft 四项、规则、机器；内嵌 `Activity` |
| `ViewIoRule` | 规则定义与聚合结果：side、key、face、mode、order、rate、reason；内嵌 `Key` 作删除身份 |
| `ViewMachine` | 机器行：machineId、方块、方块 id、健康、探测状态、order |
| `view/ViewTableBuilder` | 无状态组装：读工厂、观测、`IoForm`、`LiveNodeApply`，一次产出 `ViewTable`；最终放 view，依赖单向 `view → factory/io/runtime` |
| `ViewTableDiff` | 两版差异：版本、表头变化、节点差异列表 |
| `ViewNodeDiff` | 单节点差异：节点字段、规则 / 机器的增删改 |

### network（非 payload）

| 类 | 功能 |
|---|---|
| `ViewPort` | 视图出口：会话、差量基线、`sync` / `refresh` / `close` |
| `CommandPort` | 写命令港口；写成功后调 `ViewPort.refresh` |
| `IdleFactoryNetwork` | 网络注册入口与协议版本 |
| `ObservationNoticeListener` | 监听观测变化，聚合失联 / 恢复并节流发 actionbar |
| `AeKeyCodec` | `AEKey` 的网络字节编解码薄包装 |

### network.payload

| 类 | 功能 |
|---|---|
| `ViewTableS2C` | 全量分片 |
| `ViewTableDiffS2C` | 差量 |
| `ViewTableRequestC2S` | 同步请求：containerId + knownRevision |
| `FactoryCommandC2S` / `S2C` | 写命令与回执 |
| `FactoryLinksRequestC2S` / `FactoryLinksS2C` | 绑定杖链接快照 |
| `FactoryPassiveIoViewC2S` / `S2C` | 列表 / 磁贴偏好 |
| `FactoryTerminalSortC2S` / `S2C` | 排序偏好 |

## 关键约束

- 视图表只读，构建它的代码不得修改配置、不得写档。
- 状态一律由服务端算好；客户端不推导在线 / 缺机 / 速率，只做颜色等表现映射。
- 表里不放每 tick 必变的原始计数；每机器活动只在服务端内部用于聚合，不上线。
- 差量基线仅在终端打开期间保留，最后一个会话关闭即丢弃。
- 依赖方向：`network → view`、`client → view`；`view` 不引用 `network` / `client`。
- 包结构变化递增 `PROTOCOL_VERSION`（本轮 39 → 40）。
