# 13-堆叠与多方块

> 状态：讨论中
> 最后更新：2026-11-04
> 目标：确定堆叠机器与多方块机器的分层、数据模型与绑定交互。
>
> 2026-11-04 数据层重构已确认，最新结论以 [15-节点数据层重构确认](15-节点数据层重构确认.md) 为准；本文件保留早期讨论与背景。

## 【用户已确认】

### 分层

- 三层：**节点（逻辑设备）→ 机器（加工单元）→ 方块（BlockKey）**。
- **多方块机器就是一个「机器」**，落在机器层，不是「多个机器」拼起来。
- 堆叠的语义因此清晰：**1 节点 : 1 机器**是普通机器，**1 节点 : N 机器**是堆叠。
- 4 个状态由两层数量决定：

| 状态 | 机器数 | 每台机器方块数 |
|---|---|---|
| 单台 | 1 | 1 |
| 堆叠 | N | 1 |
| 多方块 | 1 | M |
| 堆叠多方块 | N | M |

### 硬需求

- **堆叠多方块必须有**：这是写这个模组的场景之一，不是可选项。数据模型现在就留出空间，不能等以后再改。

### 绑定交互

- 绑定杖有两类入口进入「编辑态」：
  - 世界里：**蹲下右键**某台机器 → 进入这台机器的编辑态；
  - 终端里：点机器行的 `+` → 同样进入。
- 编辑态内：
  - **右键** = 加入一个方块 / 一台机器；
  - **左键** = 移除；
  - **蹲下右键空气** = 退出。
- 加入的方块如果已属于别的机器组 → **拒绝 + 提示**，不抢占。
- 删除语义沿用现状：删整台机器 / 节点，不提供「单成员删除」。
- 堆叠的 provider 派单必须**轮流**，不能总塞第一台。

### 绑定方案（2026-11-04）

- 采用**方案 A：粘性编辑态（会话式）**。
  - 蹲下右键 = 打开 / 新建 / 切换当前节点；右键 = 把机器加入当前节点；左键 = 移除该机器；蹲下右键空气 = 退出。
  - Ctrl + 右键 = 把 6 邻接同 id 的机器整批加入当前节点。
  - 会话按玩家存内存、带过期，不写档；节点第一次创建即写档。
- 先只做**堆叠节点**（一个节点挂多台单方块机器），多方块暂缓。
- **方案 B（源-目标连线）**保留给后续的多方块机器绑定。

## 【Agent 建议·未确认】

### 数据模型

```java
final class Machine {
    UUID id;                 // 创建时确定，之后不再从坐标推导
    List<BlockKey> blocks;   // blocks.get(0) 是主方块
}

final class MachineNode {
    UUID id;
    List<Machine> machines;
    MachineIoGroup io;       // 规则在节点上，不在机器上
    MachineProvider provider;
    int lastServedMachine;   // 轮流派单游标
}
```

- `Machine` 的字段从 `pos` 改成 `blocks` 列表；`MachineRef` 可保留名字，内容换掉。
- **主方块固定为 `blocks.get(0)`**，不另设 `core` 字段：普通机器和堆叠只有 1 个方块，`get(0)` 就是全部；多方块的 `get(0)` 就是核心。一个规则覆盖三个状态。
- 主方块**不可替换**：挖掉按失联处理，玩家重新绑。理由：主方块决定 id，换主方块等于换身份，规则 / 样板 / 失联记录全要重定向。

### 身份

- 机器 id = `blocks.get(0)` 的推导值，创建时写入后固定。
- 读档校验放宽为：`id == blocks.get(0)` 的推导值。旧档 `blocks = [pos]` 天然兼容。
- 节点 id 在 1:1 时沿用机器 id，兼容旧档。

### 观测

- `Health` 增加 **`PARTIAL`**：多方块的主方块在、某个端口没了。
- `PARTIAL` 仍然执行 IO，只跳过缺失的方块；不当 `MISSING` 处理。
- 工作状态从 `blocks.get(0)` 读。

### IO 执行

```
for machine in node.machines:      ← 轮流起点 = lastServedMachine
    for block in machine.blocks:
        for face in 规则的面 / 探测到的面:
            尝试搬运
```

- `ResourceSpec` **不需要加字段**：规则作用于「机器的每个方块」，不绑定具体方块。
- 轮流游标记在节点上，按 machine 轮转；一台塞满再下一台，而不是总塞第一台。

## 【用户已推翻】

- （2026-11-04）以「最近的已绑定机器」作为编组目标：A / B 两组挨着放时无法判断。
- （2026-11-04）绑定杖三个模式的切换方案（单台 / 堆叠 / 多方块）：模式只表达「做什么」，不表达「加到谁」，两组并存时无从下手。
- （2026-11-04）终端拖拽合并作为主路径：改为「终端 `+` 按钮 + 蹲下右键进入编辑态」。
- （2026-11-04）方案 C「连通群即节点」（Ctrl 连通群直接建节点、无会话批量）：否定。

## 待定

- **编辑态里怎么分段「新机器」**（多方块的第几座）：
  - A 按方块类型：右键的方块类型等于已知主方块类型 → 新机器；否则 → 当前机器的端口；
  - B 按模板：第一台机器绑完后记下端口的相对偏移，之后只右键主方块、自动匹配；
  - C 显式动作：编辑态里再蹲下右键 = 开始新机器（与「进入 / 退出编辑态」抢手势）。
  - Agent 倾向 v1 用 A，B 留作后续。
- **堆叠多方块的绑定流程**：每座结构完整绑一遍（笨但无新概念），还是模板复制（省手但要新数据对象）。
- **编辑态的视觉反馈**：进入后动作栏 / 绑定杖 tooltip 怎么提示「正在编辑 熔炉 ×8」。
- **上限**：节点最多几台机器、单台机器最多几个方块、每侧规则数 × 机器数的总预算。
- **端口是否区分输入 / 输出**：现在靠运行时探测（能塞 / 能抽），双向口会误判；加 `PortKind {IN, OUT, BOTH}` 则 UI 和规则都要变。
- **终端里怎么显示堆叠多方块**：徽标 `×8` + `▣` 是否够，还是要显示「8 座 × 3 方块」。
- **删掉最后一台机器后**，节点自动删除还是保留空节点。
- **多方块的 `PARTIAL` 状态在终端里怎么表达**：颜色 / 文字 / 徽标。
- **节点管理终端的形态**（2026-11-04）：底部固定操作条 / 列表内联展开 / 右键菜单 / 行内双图标 / 双击进详情页 / 顶栏变操作栏，六选一或组合；倾向「详情页 + 行内定位」。
- **「倍增」与「复制规则」的语义**：复制节点配置到新节点、复制机器成员、还是批量扩建。
- **节点管理终端和被动 IO 终端是同一屏的两个视图，还是两个独立屏**。
