# 06-机器对象归属

> 状态：讨论中
> 最后更新：2026-10-31
> 标记：【用户已确认】/【用户想法·待确认】/【Agent 建议·未确认】/【用户已推翻】；技术判断归入 Agent 建议。
> 目标：去掉 Line，只保留 Machine；明确 Machine 由谁持有、全局逻辑绑定在哪里。

## 【用户已确认】

- Line 不再是必须对象；对象简化为 Machine。
- 需要有一个全局性的逻辑，不能只靠 AE2 的边缘设备。
- Factory 对象绑定 ME 网络；机器绑定杖把机器绑到该网络的 Factory。
- 配置在机器失联时保留（ADR-032）。

## 【用户想法·待确认】

- 全局逻辑的“本体”绑定在哪里：ME grid / 服务器服务 / 锚点，尚未定。

## 【Agent 建议·未确认】

- Factory（网络）持有 `MachineLibrary`；Machine 是唯一配置实体；`MachineHandle` 是运行时对象。
- 配置只由服务端 `FactoryService` / UI 修改；运行时只读。
- 不把配置挂到机器 BE 的 attachment：会和 ADR-032 冲突（拆方块丢配置）。
- 全局逻辑可做成 `IGrid` 自定义 service（`GridServices.register`），或 `FactoryRuntime` 的 grid → Factory 索引；需要 spike。
- IO 按机器遍历，不按 Line。
- AE2 机器分类：基础设施 / 存储 / 合成控制面不作为管理对象（drive、分子组装机、pattern provider、CPU、interface 等）；AE2 加工机器是否纳入由配置 / 标签决定，v1 可先全排除 `ae2:`。
- AE2 是“宿主持有 + 网格聚合 + 边缘设备 tick / IO”，不是中心扫描所有机器。
- 我们无线、无边缘设备，Factory 是中心 agent；中心 tick 是产品形态的结果。

## 【用户已推翻】

- Line 作为数据对象 / 产线执行链。
- 一人一个 Factory。

## 待确认

- Line 是否保留为 UI 分组标签。
- 全局逻辑绑定方式（`IGrid` service vs 服务器级 registry）。
- 样板访问终端是否要桥；是否提供公开 API。
