# 17-终端排序功能

> 状态：**讨论中**（2026-11-11）：用户已确认档位、按钮形态与持久化，实现计划待写。
> 最后更新：2026-11-11
> 目标：两个终端加统一的排序入口、四档排序与升降序，偏好存物品组件。

## 一、已确认

- 【用户已确认】节点管理终端与被动 IO 终端都要排序入口，放界面左侧 AE2 工具栏。
- 【用户已确认】四档：名称（节点显示名）、id（节点对应的机器 id）、数量（节点机器台数，
  降序，同值按名称）、状态（按展示状态排）。
- 【用户已确认】两个按钮：一个切档位、一个切升降序，形态与 AE2 终端一致。
- 【用户已确认】图标全部复用 AE2 现成图标，四档各对应一个 `SORT_BY_*`，不追求语义匹配。
- 【用户已确认】状态档顺序按灯色红→灰：失联 → 健康过期 → 缺机 → 未探测 → 输入堵塞 →
  仓库缺料 → 运行 → 可输入 → 空闲 → 无规则 → 未知。
- 【用户已确认】默认档位＝名称。
- 【用户已确认】排序偏好持久化到物品的 `ae2:exported_settings` 组件，跟列表 / 卡片视图同源，
  两个终端各自记住自己的选择。

## 二、方案（Agent 建议·未确认）

- 前提：节点状态已收口为服务端 `NodeStatus`（ADR-040，协议 32），状态档只读展示档
  （`FactoryStatus.Kind`），排序层不再自己判断状态。
- 排序单位是节点：节点终端一行＝一个节点，被动 IO 一块＝一个节点；规则行与成员行不参与
  排序（规则下标是动作身份，重排会让点击落到别的规则上），列表 / 磁贴两种视图共用一套顺序。
- 排序在客户端 model 的 `rebuild()` 里做：过滤之后、生成行 / 块之前；重排后重建排版并夹紧
  滚动。点击命中用当帧排版下标，展开 / 改名 / 删除用 `nodeId`，重排不会让动作串位。
- 排序枚举与设置键放 `menu`（服务端也要读），排序比较器与按钮放 `client.screen`；方向值
  优先复用 AE2 的 `SortDir`。
- 两个终端 host 都要有 `IConfigManager`（节点终端目前没有）；新增排序设置包（C2S / S2C），
  `PROTOCOL_VERSION` 递增到 33。
- 同值兜底：名称 → 登记下标；稳定排序保证每秒快照不换位。
- 改名框 / 删除确认框打开时冻结当前顺序，避免误点。

## 三、待定

- 【待定】「id」的确切含义：节点类型方块注册名（`typeBlockId`），还是节点 / 机器 UUID 短 id？
  Agent 建议按 `typeBlockId` 注册名：搜索字段已有它，离线也有值。
- 【待定】方向按钮语义：全局方向（AE2 语义，默认升序），还是每档有自然方向（数量降序、
  名称升序）？用户把「数量降序」写进档位定义，双按钮又要跟 AE2 一致，两者需要对齐。
- 【待定】升降序默认值；id 档、名称档同值时的兜底顺序。
- 【待定】工具栏顺序：帮助 → 终端高度 → 排序 → 方向 →（被动 IO 再加视图切换）。
- 【待定】方向按钮图标：`ARROW_UP` / `ARROW_DOWN` 还是 `S_ARROW_*`。

## 四、范围外

- 【用户已确认】节点终端展开后的成员行仍显示节点级状态灯；成员级状态要另开一轮——`MemberView`
  缺每台机器「在干什么」的字段，属于协议 +1 的独立事项，不阻塞排序。
