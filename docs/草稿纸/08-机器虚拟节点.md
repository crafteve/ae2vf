# 08-机器虚拟节点

> 状态：讨论中
> 最后更新：2026-10-31
> 标记：【用户已确认】/【用户想法·待确认】/【Agent 建议·未确认】/【用户已推翻】；技术判断归入 Agent 建议。
> 目标：判断是否把虚拟化粒度从 Factory 下放到“机器的虚拟 bus / provider 节点”。

## 【用户已确认】

- `PatternProviderLogic` 是 BE 专用的，我们不需要用它；虚拟样板供应器可以拆开实现它的功能。
- 不把 Factory 作为虚拟节点；把 AE2 的 bus / provider 虚拟化，给这些虚拟 bus / provider 注册虚拟节点。
- 一机一节点。
- 样板访问终端按机器分容器，这是目标。
- 频道按虚拟节点数量收。
- 机器定义要留扩展空间：一个机器对象可以把 n 个方块实体当成一个大机器处理（批量熔炉、多方块、自定义对象），以后再实现。
- 频道绑定杖：绑定某个方块的某个面，把虚拟节点 / hub 挂到那个面。
- 不是预留，是把虚拟连接排在物理连接前面，让 pathing 先分给虚拟；虚拟拿 12 个后，剩余给物理。
- 32 个虚拟节点全请求就吃满，物理拿 0；只让 12 个请求，就剩 20 给物理。

## 【用户想法·待确认】

- Factory 可以退成虚拟网关 / 经纪人，不一定是节点；这一条用户自己还不确定。

## 【Agent 建议·未确认】

- Factory 退化为 controller：不持有节点，只负责机器、IO、样板、ACL、节点生命周期。
- 每个逻辑机器一个 `MachineAgent`（owner），挂一个非世界 `ManagedGridNode`；节点服务按需：
  - `ICraftingProvider`：这台机器的样板；
  - `IGridTickable`：这台机器的虚拟 import/export bus tick；
  - owner 实现 `PatternContainer`：样板访问终端按机器看到容器。
- 节点可 `REQUIRE_CHANNEL` / `setIdlePowerUsage`；一机一节点时，频道自然按机器数计。
- 节点通过逻辑连接挂到 WAP 节点；WAP 节点本身是普通节点（max 8 频道），一台 WAP 大约能带 8 个设备（含自己）；更多机器就加 WAP 或做虚拟 dense hub（32）。
- 频道入口必须是真实节点：WAP / cable / part 接在控制器或线缆上；虚拟节点只能逻辑挂到真实节点，不能凭空“从控制器面”拿频道。直连 controller 节点技术上可以 `createConnection`，但绕过面/拓扑，不作为设计。
- 频道不是总池：不要手工算“总频道 - 已用”，让虚拟节点 `REQUIRE_CHANNEL` 走 AE2 pathing；只有逻辑连接分配不生效时，才考虑自定义预算。
- 控制器一面 32 是简化说法：面到致密线/连接是 32，普通线/普通节点是 8；WAP 是普通节点，所以一个 WAP 约 8。
- 一个网络仍只允许一个 Factory；Factory 创建 / 销毁它名下的机器节点。
- 频道绑定杖技术上可行：射线选面 → `GridHelper.getExposedNode(level, pos, side)` 拿该面暴露的 `IGridNode` → `GridHelper.createConnection(虚拟节点/hub, 该节点)`；但它只是接在已有节点上，不造频道。
- pathing 遍历的是节点的连接表：`GridNode.getPossibleOptions()` 返回 `connections` 的拷贝，`addConnection` 追加；连接表顺序就是处理顺序，不需要靠 `PREFERRED` 队列。
- 把虚拟 hub 的连接插到物理连接前面，虚拟子树就会先分频道；之后才轮到物理设备。12 个虚拟节点请求就吃 12，剩下给物理；32 个全请求就吃满，物理拿 0。
- 没有公开的“插到连接表最前”API：`GridHelper.createConnection` 只追加。要实现只能：先在物理连接之前创建虚拟连接；反射/AT 重排 `connections`；或者拆掉再重建物理连接（会短暂分裂，风险高）。
- 一个虚拟 dense hub 挂在面上，hub 自己的连接表由我们控制；面节点上只需要把 hub 这一条连接排到物理连接前面，不用排 32 条。
- 专用面仍然是最稳的退路：面只挂虚拟 hub，物理走其他面，不需要重排。
- 建议：绑定对象限制为真实可载频道的节点（cable / part / WAP），不直接绑 controller；一个域绑一个 hub，机器节点挂 hub；先作为高级功能，v1 先用 WAP。
- 风险：节点数量、连接表重排的内部访问、频道分配、持久化、grid 分裂/合并；需要 spike。
