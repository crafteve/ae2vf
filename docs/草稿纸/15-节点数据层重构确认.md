## 【用户已确认】

### 模型与身份

- 三层：**节点 → 机器 → 方块**。四种状态由“机器数 × 每台机器方块数”表达：单台 1×1、堆叠 N×1、多方块 1×M、堆叠多方块 N×M。
- **节点 id 随机生成**，与机器 id、方块 key 无关。
- **机器 id 随机生成**，与方块 key 无关；加/删方块、换主方块都不改机器 id。
- **方块 key 只表示位置**（维度 + 坐标），用于观测、占用、路由，不派生机器或节点 id。
- **机器不存维度，节点也不存维度**；维度在方块上。
- 节点内的机器**不要求同维度**。
- 同一台机器内部的方块**也不要求同维度**；只要有一部分方块不可用，整台机器就是 OFFLINE。维度不改变 IO 逻辑：能读到的方块照常跑，读不到的方块让整台机器离线。
- 节点内的机器**必须同一种方块 id**：单方块机器看它的唯一方块，多方块机器**只认主方块 id**；部件（输入输出总线等）不参与类型判定。
- 机器 missing 后，原地被别人放了不同方块 → **不认那个新方块**，机器保持 missing；同 id 方块回来才恢复。
- **全离线自动迁移**：只要节点里还有机器在线，缺失机器原地出现不同方块不认；当节点**所有机器都离线**，且所有机器的主方块都变成**同一个新方块 id**（不是空气、不是各不相同的类型）时，节点自动迁移成新类型——节点 id、规则、样板、名字、机器 id 都保留，只更新类型。部分换、换得不一样、主方块是空气都不迁移。
- **堆叠机器没有“主方块”概念**；主方块只属于多方块机器。多方块机器第一次蹲下右键的方块作为这台机器的主方块 / 展示块，不一定是模组真正的控制器。
- 多方块机器**不加邻接 / 结构约束**；主方块之外的部件可以是不同方块（如输入输出总线）。
- 旧档不迁移；当前是开发状态，测试世界可重建。

### 健康

- **MachineHealth 只有 ONLINE / OFFLINE**：所有方块都在 = 在线；任何一个方块不在 = 离线。
- **NodeHealth 只有 ONLINE / PARTIAL / OFFLINE**：全部机器在线 = 在线；部分在线 = 部分（缺机）；全部离线 = 离线。
- 未探测过的机器 / 节点按 **OFFLINE** 处理，tooltip 写“未探测”，不新增 UNKNOWN 状态。
- 方块级 Health 仍保留未加载 / 缺失 / 维度不存在，只用于诊断与 tooltip，不再作为机器 / 节点状态。
- 不再区分“未加载 / 被拆 / 维度没了”作为机器 / 节点状态。

### IO 规则

- IO 规则**归节点**；堆叠机器共用一套规则。
- 规则作用于节点的每台机器、每台机器的每个方块，不绑定具体方块。
- IO 只跑 ONLINE 的机器；节点 PARTIAL 时，剩余 ONLINE 的机器继续跑。
- 失败原因 `OK / NO_ITEM / NO_SPACE / NO_HANDLER / REJECTED` 的语义不变；`NO_SPACE` 与 `REJECTED` 不混。
- 物品规则默认无向；流体 / FE 仍按面；路由表规则不变。

### provider 与余量

- provider 归节点；阻挡、倍增、派单都是节点级配置。一个节点一个 PatternContainer。
- 一次货只给**一台机器**；这台机器收不下的部分进**余量队列**（代码里的 `pending` 就是现有那份余量 list，不是新概念），等有空位再塞，**不拆分到别的机器**。
- 余量条目记住它属于哪台机器，只回填那一台；那台机器没了就退回 ME 网络，不转给别的机器。
- 固定倍率：明确 N。
- 智能倍率：按“一台机器能装几份”算；堆叠只支持相同机器，所以容量一致。AE 看到 N 倍的大样板；需要更多产出时 AE 发多次 N 倍货，节点依次塞入各台机器。
- 智能倍率容量探测失败时**回退 ×1**，tooltip 标“无法估算”。
- 倍增时输入和输出**同倍**，不改变配比。
- 多方块：provider 对整台机器的**所有方块**开面，优先主方块，再逐个部件；阻挡 / 回收也扫所有方块。

### 绑定（绑定杖草稿）

- **不做服务端会话，不做时间限制**。
- 绑定过程存在**绑定杖物品组件**里（客户端草稿）；完成时一次上传，服务端全量重校验后原子应用。
- 草稿**不跨登录保留**；物品组件足够，退出重进丢失可接受。
- 客户端只做简单核验（主手、重复块、同 id 等）；服务端不信任客户端。
- 模式：SINGLE / STACK / MULTIBLOCK / STACKED_MULTIBLOCK；**蹲下滚轮**切换模式。
- SINGLE 模式下蹲下右键方块：不建草稿，动作栏提示“先蹲下滚轮切到堆叠 / 多方块模式”。
- 普通左右键只对“未接入”或“1 机器节点”生效；堆叠 / 多方块节点成员只提示“蹲下右键进入编辑”，不删不改。
- STACK：蹲下右键定第一块 / 开草稿，右键加机器，蹲下右键空气提交。
- MULTIBLOCK：蹲下右键定主方块 / 开始机器，右键加部件，蹲下右键空气完成并提交。
- STACKED_MULTIBLOCK：蹲下右键开新机器；右键加部件；蹲下右键空气结束当前机器；当前没有机器时再蹲下右键空气提交整份草稿；动作栏写提示。
- 编辑已有节点：世界蹲下右键已有成员，或节点终端 `+`，把 nodeId 写进草稿；提交时追加到该节点。
- 草稿非空时**不允许切模式**，先完成或取消。
- 取消草稿：**蹲下 + 左键空气**。
- 绑定**不校验距离**；不做防作弊。

### 终端

- **v1 `FactoryScreen` 是废弃兜底**：只做编译层面的字段机械适配，不改设计。
- **v3 `FactoryPassiveIo*` 改为节点大卡片**：堆叠节点图标右下角用原版物品数量标识画机器数；节点卡片下编辑节点 IO 规则。
- 多方块节点在 v3 先做占位：主方块图标 + 方块数 tooltip + 节点规则，不做结构图。
- v3 节点卡片删除 = 删整个节点；单成员移除只走编辑态。
- 节点终端 `+` 接编辑草稿；“编辑中”由客户端读绑定杖草稿判断，不新增服务端会话字段。
- 规则动作包改为传 `nodeId`；v1 兜底做机械适配。

### config 与协议

- 上限全部进 config，默认 `-1` 无上限；注释中英双语。
- 网络解码保留固定安全硬上限，防恶意包；注释说明它不是玩法上限。
- 协议版本递增；解码侧用 `min(config, hard cap)`。
- config 改小后**不删已有数据**，只阻止继续新增。
- 旧档不迁移。

## 【用户已推翻】

- “1 机器 = 1 节点 = 1 方块”。
- “节点 id = 机器 id”“机器 id = 主方块 key 派生”。
- “机器 / 节点存维度”“节点内机器必须同维度”“单台机器内部方块必须同维度”。
- “机器级 PARTIAL、副方块缺失仍跑 IO、只跳过缺失方块”。
- “服务端粘性会话 + 60 秒过期”。
- “倍率把一份货拆给 N 台机器”。
- “多方块暂缓、不做创建入口”。
- “多方块部件必须邻接 / 有结构约束”。
